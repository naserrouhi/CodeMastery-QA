# Q2-2: What are common performance issues in Node.js and how do you resolve them?

1. Blocking the Event Loop

   - Problem:
        - Heavy computations (e.g., loops, encryption) block the single-threaded event loop.

   - Fix:
     - Offload to worker threads or background services.

   - Example:

```ts
// Use Worker Threads
const { Worker } = require('worker_threads');
new Worker('./heavy-task.js');
```

2. Memory Leaks

   - Problem:
     - Unreleased resources (e.g., global variables, event listeners not removed) consume memory over time.

   - Fix:
     - Use tools like `clinic.js`, `heapdump`, or Chrome DevTools.
     - Watch out for:
       - Large global objects
       - Forgotten timers or listeners

3. Too Many Synchronous Operations

   - Problem:
     - Using sync I/O like `fs.readFileSync` blocks everything.

   - Fix:
     - Use async/non-blocking versions:

```ts
await fs.promises.readFile('file.txt');
```

4. Unoptimized Database Queries

   - Problem:
     - N+1 queries
     - Missing indexes
     - Long joins or large payloads

   - Fix:
     - Profile queries (e.g., with `EXPLAIN`)
     - Use ORMs wisely (with eager/lazy loading)
     - Batch requests or use caching (e.g., Redis)

5. Unnecessary Network Calls / Redundant APIs

   - Problem:
     - Calling 3rd-party APIs repeatedly
     - Not caching repeated responses

   - Fix:
     - Use HTTP caching headers, `ETag`
     - Add Redis/in-memory cache:

```ts
// Example with node-cache
const NodeCache = require("node-cache");
const cache = new NodeCache();
```

6. Inefficient Middleware in Express.js

   - Problem:
     - Middleware doing heavy logic or logging every request synchronously.

   - Fix:
     - Use middleware like `morgan` efficiently (in dev only)
     - Avoid parsing large bodies unless necessary
     - Move security checks and logic early in chain

7. Too Many Dependencies

   - Problem:
     - Heavy npm modules slow down startup and increase memory use.

   - Fix:
     - Audit `node_modules` regularly
     - Remove unused libraries
     - Use smaller alternatives (e.g., `got` instead of `axios` for lightweight requests)

- Tools to Detect & Fix:

  - `clinic.js` – diagnose bottlenecks visually
  - `node --inspect` – use Chrome DevTools for memory/CPU
  - `pm2` – manage clustering and monitoring
  - `autocannon` – load testing
