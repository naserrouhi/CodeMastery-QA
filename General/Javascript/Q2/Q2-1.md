# Q2-1: How do you design and consume RESTful vs GraphQL APIs? When would you choose one over the other?

- RESTful API

  - Consume in React

```tsx
import { useQuery } from 'react-query';

const fetchUsers = () => fetch('/api/users').then(res => res.json());

function UserList() {
  const { data, isLoading } = useQuery('users', fetchUsers);
  return isLoading ? 'Loading...' : data.map(u => <div>{u.name}</div>);
}
```

- GraphQL

```graphql
query {
  user(id: 1) {
    name
    email
    posts {
      title
    }
  }
}
```

  - Consume in React (Apollo Client)

```tsx
import { gql, useQuery } from '@apollo/client';

const GET_USER = gql`
  query {
    user(id: 1) {
      name
      posts { title }
    }
  }
`;

function User() {
  const { data, loading } = useQuery(GET_USER);
  return loading ? 'Loading...' : <h1>{data.user.name}</h1>;
}
```

- When to Use Each

| Feature                           | REST                       | GraphQL                        |
| --------------------------------- | -------------------------- | ------------------------------ |
| Simpler, caching                  | Native HTTP support        | Needs custom caching (Apollo)  |
| Multiple resources in one request | (multiple endpoints)       | (single query)                 |
| Precise data fetching             | Over-fetch or under-fetch  | Exact fields                   |
| Evolving frontend needs           | New endpoints often needed | Schema stays, clients change   |
| Strong backend control            | More rigid                 | Needs proper schema & security |
| Easy to implement                 | Simple                     | More tooling/setup             |
