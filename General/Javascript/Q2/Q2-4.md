# Q2-4: Explain how to secure a Node.js API and protect it against common OWASP vulnerabilities

1. Authentication & Authorization

   - Use JWT (JSON Web Tokens)
     - Sign with a secret or private key.
     - Store in `Authorization: Bearer <token>` header.
     - Don't store JWTs in localStorage on frontend—prefer `HttpOnly` cookies.

   - Role-based access control (RBAC)
     - Implement middleware to check user roles/permissions.

```js
// auth.middleware.js
function authorizeRoles(...allowedRoles) {
  return (req, res, next) => {
    if (!allowedRoles.includes(req.user.role)) return res.status(403).send('Forbidden');
    next();
  };
}
```

2. Input Validation and Sanitization

   - Use a library like Zod, Joi, or express-validator
   - Validate all input: query, body, params, headers.

```ts
// user.validator.ts (Zod)
const loginSchema = z.object({
  body: z.object({
    email: z.string().email(),
    password: z.string().min(6),
  }),
});
```

   - Prevent NoSQL/SQL Injection
     - For MongoDB: use Mongoose, never trust raw `req.body`
     - For SQL: use parameterized queries or ORM like Prisma/Sequelize

3. Rate Limiting and Throttling

   - Use `express-rate-limit` to prevent brute force/DDoS:

```js
const rateLimit = require('express-rate-limit');
app.use(rateLimit({ windowMs: 15 * 60 * 1000, max: 100 }));
```

4. CORS Configuration

   - Only allow trusted domains:

```js
const cors = require('cors');
app.use(cors({ origin: ['https://yourapp.com'], credentials: true }));
```

5. Secure HTTP Headers

   - Use `helmet` to set safe headers:

```js
const helmet = require('helmet');
app.use(helmet());
```

   - Includes headers like:
     - `X-XSS-Protection`
     - `Strict-Transport-Security`
     - `X-Content-Type-Options`

6. Prevent XSS & CSRF

   - Use Zod or DOMPurify (on frontend) to clean HTML.
   - Avoid rendering unescaped user input in templates.
   - Use CSRF tokens if your API supports cookies (e.g., with `csurf` middleware).

7. HTTPS & Secure Cookies

   - Force HTTPS in production using reverse proxy or `helmet.hsts()`.
   - Use `Secure`, `HttpOnly`, `SameSite` flags on cookies.

8. Logging, Monitoring & Error Handling

   - Use `winston`, `pino`, or `bunyan` for structured logging.
   - Log suspicious activity but never log passwords or tokens.
   - Use centralized tools like Sentry, Logtail, or Datadog.

9. Use a .env and Avoid Secrets in Code

   - Never hardcode passwords, DB URLs, or tokens.
   - Use `dotenv`, `.env`, and tools like Vault or AWS Secrets Manager.

10. Keep Dependencies Updated

    - Use `npm audit fix` or tools like:
      - [Snyk](https://snyk.io/)
      - `npm-check-updates`
    
    - Remove unused packages

- Content Security Policy (CSP)

  - If you're rendering views or building SSR apps, enforce a strict CSP to prevent injection.
