# Q2-3: How would you structure a Node.js Express backend for scalability and maintainability?

1. Folder Structure (Modular & Layered)

```plaintext
src/
│
├── config/               # App config (env, DB, etc.)
│   └── database.js
│
├── routes/               # Express route definitions
│   └── user.route.js
│
├── controllers/          # Route handlers (business logic entrypoint)
│   └── user.controller.js
│
├── services/             # Business logic layer
│   └── user.service.js
│
├── models/               # DB models (e.g., Sequelize, Mongoose)
│   └── user.model.js
│
├── middlewares/          # Custom Express middlewares
│   └── auth.middleware.js
│
├── validators/           # Validation schemas (Zod, Joi, Yup)
│   └── user.validator.js
│
├── utils/                # Helpers, loggers, etc.
│   └── logger.js
│
├── app.js                # Express app config
└── server.js             # Entry point
```

2. Layered Responsibilities

   - Controller: Parses request/response, handles HTTP-specific concerns.
   - Service: Pure logic, reusable across controllers/jobs.
   - Model: Database interaction only (ORM/ODM).
   - Middleware: Cross-cutting concerns (auth, logging, etc.)

3. Use Dependency Injection (Optional but scalable)

   - Helps with testability and decoupling logic.

4. Environment-based Config

   - Use `dotenv`, and centralize config:

```js
// config/index.js
module.exports = {
  port: process.env.PORT || 3000,
  dbUrl: process.env.DB_URL,
};
```

- 5. Validation Layer

  - Use Zod, Joi, or Yup to validate requests.

```ts
// user.validator.js (Zod)
const createUserSchema = z.object({
  body: z.object({
    email: z.string().email(),
    password: z.string().min(6),
  }),
});
```

- 6. Testing Ready

  - Use `Jest` or `Mocha`
  - Mock services in controller tests
  - Folder `__tests__` or `tests/` with separate test files

- 7. Scalability Tips

  - Use PM2 for clustering and restarts
  - Add Redis for caching sessions or frequent reads
  - Decouple with message queues (e.g., RabbitMQ) if needed
  - Split features into modules/domains when app grows

8. Advanced (When You Grow)

   - Use TypeScript for type safety
   - Switch to Clean Architecture or DDD-style folder structure
   - Use Swagger/OpenAPI for API docs
   - Add Rate Limiting, CORS, Security headers
