# Q5-2: What is your experience with Vercel/Netlify and their CI/CD pipelines?

1. Vercel & Netlify CI/CD – Overview

   - Both platforms offer zero-config CI/CD:

     - Auto-deploy on Git push (GitHub, GitLab, Bitbucket).
     - Create Preview Deployments for every branch or PR.
     - Atomic deployments – each deployment is immutable and isolated.

2. Experience Using Them

   - Vercel

     - Best for Next.js (tight integration).

     - Steps typically followed:
       - Connect GitHub repo to Vercel.
       - On `push` to `main` → Production deployment.
       - On `PR` → Unique preview URL (great for reviews).

     - Used features:
       - Environment Variables
       - Custom domains
       - Edge Functions / Serverless API routes
       - Image optimization

     - Example workflow:

  ```bash
  git push origin main
  # Triggers auto build and deployment
  ```

   - Netlify

     - Best for static sites, JAMstack apps, React, Vue, Svelte, etc.

     - Used for:
       - Static React apps with Netlify CLI
       - Netlify Functions for serverless endpoints
       - Form handling and redirects

     - Custom build commands and deploy previews supported.
     - Can set up **split testing** and branch-based routing.

3. CI/CD Configurations

| Feature              | Vercel                     | Netlify                     |
| -------------------- | -------------------------- | --------------------------- |
| Git integration      | Yes (auto builds on push)  | Yes                         |
| Branch previews      | Yes (PR previews)          | Yes (Deploy Previews)       |
| Build customization  | `vercel.json` or dashboard | `netlify.toml` or dashboard |
| Serverless functions | API Routes (Next.js)       | Netlify Functions           |
| Rollbacks            | One-click rollback         | Rollback to previous deploy |

- ips & Best Practices

  - Use `.env` files locally and define env variables in dashboard.
  - Keep build artifacts small (optimize images, lazy load).
  - Use monorepo support for multiple apps.
  - For sensitive data: Never expose in frontend env.
