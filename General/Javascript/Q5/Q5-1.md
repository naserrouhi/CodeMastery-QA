# Q5-1: How does serverless deployment differ from traditional server-based deployment?

1. Core Differences

| Feature           | Traditional Deployment              | Serverless Deployment                               |
| ----------------- | ----------------------------------- | --------------------------------------------------- |
| Server Management | You manage servers (e.g., EC2, VPS) | No server management – handled by cloud provider    |
| Scaling           | Manual or auto-scaling setup        | Automatic scaling per request                       |
| Billing           | Pay for uptime (24/7), even if idle | Pay only for actual usage (invocations/time)        |
| Deployment Unit   | Full application/service            | Function (or endpoint) as a unit                    |
| Cold Start        | N/A – servers always on             | Possible cold starts (small delay on first request) |

2. Examples

   - Traditional (Server-Based)
     - Deploy a Node.js app to a VPS (like DigitalOcean or EC2)
     - Install Node, MongoDB, reverse proxy (Nginx), etc.
     - Manage uptime, logs, health checks, patch updates
     - Example:

  ```bash
  ssh into server → git pull → pm2 restart app
  ```

   - Serverless (FaaS)

     - Deploy individual functions to platforms like:
       - AWS Lambda
       - Vercel (Next.js)
       - Netlify Functions
       - Azure Functions

     - You write code, deploy, and let the provider handle the rest.
     - Example (Vercel):

  ```js
  // pages/api/hello.js
  export default function handler(req, res) {
    res.status(200).json({ message: "Hello from serverless!" });
  }
  ```

3. When to Use

| Use Serverless If...            | Use Traditional If...                                     |
| ------------------------------- | --------------------------------------------------------- |
| You want zero server ops        | You need low-latency, long-running processes              |
| You have spiky traffic          | You need full control over OS, networking                 |
| You want pay-per-use cost       | You want predictable monthly costs                        |
| You build microservices or APIs | You host large apps (e.g., ML workloads, real-time games) |
