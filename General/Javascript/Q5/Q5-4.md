# Q5-4: How do you use Infrastructure-as-Code tools like Terraform?

- Infrastructure as Code (IaC) tools like Terraform allow you to provision, manage, and version infrastructure (servers, databases, networks, etc.) using code — just like application code.

- Terraform:

  - Declarative: You describe the desired state; Terraform figures out the steps.
  - Cloud-agnostic: Supports AWS, Azure, GCP, etc.
  - Version-controlled: Store `.tf` files in Git for traceability and rollbacks.

- Basic Workflow

  1. Write config files** in `.tf` format (HCL - HashiCorp Configuration Language).
  2. Run `terraform init` to initialize.
  3. Run `terraform plan` to preview changes.
  4. Run `terraform apply` to provision infrastructure.

- Example: Provisioning an AWS EC2 Instance

  - `main.tf`

```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_instance" "my_ec2" {
  ami           = "ami-0c55b159cbfafe1f0" # Example Ubuntu AMI
  instance_type = "t2.micro"

  tags = {
    Name = "MyEC2"
  }
}
```

  - `variables.tf` (Optional)

```hcl
variable "region" {
  default = "us-east-1"
}
```

- Best Practices

  - Use modules for reusable infrastructure pieces.
  - Store sensitive data in Terraform Cloud, AWS Secrets Manager, or .tfvars (but keep it in `.gitignore`).
  - Use state backends** like S3 + DynamoDB for collaboration and locking.
  - Always run `terraform plan` before `apply`.

- Use Cases in Real Projects

  - Spin up cloud resources (EC2, RDS, S3, VPC, etc.)
  - Set up CI/CD pipelines
  - Provision Kubernetes clusters (via EKS/GKE modules)
  - Configure DNS, CDN (Cloudflare, Route53)

- Security Considerations

  - Avoid hardcoding secrets or API keys
  - Use remote state with encryption (e.g., `S3 + KMS`)
  - Follow least privilege for Terraform users/roles
