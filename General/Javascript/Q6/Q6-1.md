# Q6-1: What are the top OWASP vulnerabilities and how do you mitigate them in a full-stack app?

| Vulnerability                                 | Description                                             | Mitigation Strategies                                                                                                                 |
| --------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Broken Access Control                      | Users can access data or actions they shouldn’t         | - Implement strict authorization checks on backend.<br>- Use role-based access control (RBAC).<br>- Validate access on every request. |
| 2. Cryptographic Failures                     | Sensitive data exposure due to weak crypto or none      | - Use HTTPS everywhere.<br>- Encrypt sensitive data at rest and in transit.<br>- Use strong, vetted algorithms and libraries.         |
| 3. Injection (e.g., SQL, NoSQL)               | Attackers send malicious data to manipulate queries     | - Use parameterized queries or ORMs.<br>- Validate and sanitize all inputs.<br>- Avoid string concatenation in queries.               |
| 4. Insecure Design                            | Design flaws leading to security weaknesses             | - Use threat modeling during design.<br>- Adopt security-by-design principles.<br>- Review architecture regularly.                    |
| 5. Security Misconfiguration                  | Poorly configured security controls or defaults         | - Harden server, database, and app configs.<br>- Use secure HTTP headers (via Helmet in Node.js).<br>- Disable unnecessary features.  |
| 6. Vulnerable and Outdated Components         | Using outdated libraries or frameworks with known flaws | - Regularly update dependencies.<br>- Use tools like `npm audit`, Snyk.<br>- Remove unused packages.                                  |
| 7. Identification and Authentication Failures | Weak or broken login/authentication                     | - Use strong password policies.<br>- Implement multi-factor authentication (MFA).<br>- Securely store passwords (bcrypt, Argon2).     |
| 8. Software and Data Integrity Failures       | Code or data tampering, insecure CI/CD                  | - Verify software updates with signatures.<br>- Use secure CI/CD pipelines.<br>- Enable code signing where possible.                  |
| 9. Security Logging and Monitoring Failures   | Lack of logs or alerts for attacks                      | - Implement centralized logging.<br>- Monitor for anomalies.<br>- Alert on suspicious activity.                                       |
| 10. Server-Side Request Forgery (SSRF)        | Server is tricked into fetching unintended URLs         | - Validate and whitelist URLs.<br>- Block internal network requests.<br>- Use network segmentation/firewalls.                         |

- How to Apply These in a Full-Stack MERN App

  - Backend (Node.js/Express + MongoDB):
    - Use middleware to check authentication and authorization.
    - Validate & sanitize inputs with Zod/Joi.
    - Use parameterized MongoDB queries (avoid `$where` or raw queries).
    - Use Helmet for HTTP headers.
    - Enable CORS carefully (allow only trusted domains).
    - Store secrets in env variables, not code.
    - Use bcrypt for password hashing.
    - Keep dependencies up to date.

  - Frontend (React/Next.js):
    - Validate user input before sending.
    - Avoid rendering raw HTML or use sanitizers like DOMPurify.
    - Use HTTPS and secure cookies.
    - Implement frontend role checks but never rely solely on them.
    - Avoid exposing sensitive info in client code.
