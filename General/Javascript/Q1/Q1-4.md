# Q1-4: How would you structure a scalable React (or Next.js) application?

- Core Principles

    1. Feature-based separation (not type-based)
    2. Reusability and modularity
    3. Isolation of concerns: UI, state, business logic, API, utilities
    4. Consistent naming and folder conventions
    5. Scalable for multiple developers or large codebases

- Extra Good Practices

    1. Use TypeScript to catch bugs early.
    2. Isolate API logic inside `services/` or `features/*/service.ts`.
    3. Keep components small and focused.
    4. Use a global state library (Zustand, Redux) only when needed.
    5. Write unit and integration tests.
    6. Use absolute imports via `tsconfig.json` paths.

- Folder Structure for Next.js (App Router)

```bash
/app
  /auth
    login/page.tsx           # Route: /auth/login
    register/page.tsx
  /dashboard
    page.tsx
    layout.tsx
    /[id]
      page.tsx               # Dynamic route: /dashboard/123
  layout.tsx                 # Root layout (shared header, footer)
  page.tsx                   # Home page
  globals.css

/components                 # Reusable UI components
  Header.tsx
  Sidebar.tsx
  Button.tsx

/features                   # Business logic by domain
  /auth
    authService.ts          # Auth API logic
    useAuth.ts              # Custom hook for login/logout
    authSlice.ts            # State (Zustand/Redux)
  /dashboard
    dashboardService.ts
    useDashboard.ts

/hooks                      # Generic reusable hooks
  useDebounce.ts
  useWindowSize.ts

/services                   # Shared backend services
  api.ts                    # Axios instance or fetch wrapper
  logger.ts

/types                      # Shared TypeScript types/interfaces
  user.ts
  api.ts

/utils                      # Generic helpers
  formatDate.ts
  validators.ts

/public                     # Static assets (images, icons)

/middleware.ts              # Next.js middleware (e.g. auth redirect)
next.config.js
tsconfig.json
.env.local
```
