# Q1-3: How would you structure a scalable React (or Next.js) application?

- To structure a scalable React or Next.js app, you need to organize code in a way that supports:
- modularity, reusability, and growth as the app becomes more complex.

1. Use a Feature-Based Folder Structure (Highly Recommended)

    - Instead of separating files by type (components, styles, etc.), group them by feature/domain

```bash
/src
  /features
    /auth
      AuthPage.tsx
      authSlice.ts     # Redux or state logic
      authApi.ts       # API calls
      AuthForm.tsx
    /dashboard
      DashboardPage.tsx
      DashboardChart.tsx
      dashboardApi.ts
  /components          # Reusable UI components
    Button.tsx
    Modal.tsx
  /layouts
    MainLayout.tsx
    AuthLayout.tsx
  /hooks
    useAuth.ts
    useDebounce.ts
  /utils
    formatDate.ts
    validators.ts
  /services
    apiClient.ts       # Axios/fetch setup
    authService.ts
  /types
    user.ts
    common.ts
  /pages (Next.js)
    index.tsx
    dashboard.tsx
  /public
  app.tsx              # (React entry point)
  layout.tsx           # (Next.js App Router)
```

2. Use Centralized API Handling

    - Create a service layer (`/services`) to abstract away fetch logic.
    - Use tools like `axios`, `react-query`, or `SWR`.

3. Manage State Wisely

    - Use `useState`/`useReducer` for local state.
    - Use `Redux`, `Zustand`, `Jotai`, or `Recoil` for global state.
    - Keep business logic out of components.

4. Use Environment Configs

    - `.env.local`, `.env.production` for API URLs, keys, etc.

5. Add Tests

    - Unit: Jest, React Testing Library
    - E2E: Cypress or Playwright

---

6. Use TypeScript

    - Enforce contracts and improve refactor safety.

7. Modularize Styles

    - Use CSS Modules, Tailwind CSS, or Styled Components for isolation and reuse.

8. Add Error Boundaries and Logging

    - Capture errors gracefully using custom `<ErrorBoundary>` components.

9. Follow Clean Code Practices

    - Keep components small and focused.
    - Avoid deeply nested props (use context or state management).

- Folder Structure Example of Next.js

```bash
/app
  /dashboard
    /[userId]
      page.tsx         # Dynamic route: /dashboard/123
      loading.tsx
      error.tsx
    layout.tsx         # Nested layout for dashboard pages
    page.tsx           # /dashboard home
  /auth
    login/page.tsx     # /auth/login
    register/page.tsx  # /auth/register
  /api
    /auth
      login/route.ts   # API route: POST /api/auth/login
  layout.tsx           # Root layout (HTML shell)
  page.tsx             # Root page (home)
  globals.css

/components
  Button.tsx
  Header.tsx
  Sidebar.tsx

/features
  /auth
    authSlice.ts       # Global state logic (Zustand, Redux, etc.)
    authService.ts     # API service abstraction
    useAuth.ts         # Custom hook
  /dashboard
    dashboardService.ts
    useDashboardData.ts

/hooks
  useDebounce.ts
  useOutsideClick.ts

/lib
  db.ts                # DB client (e.g., Prisma)
  auth.ts              # Auth utilities
  logger.ts

/services
  axios.ts             # Axios config
  api.ts               # Wrapper for API calls

/types
  user.ts
  dashboard.ts

/utils
  formatDate.ts
  validators.ts

/public
  /images
    logo.png

/middleware.ts          # Middleware (e.g., auth protection)

/.env.local
next.config.js
tsconfig.json
```
