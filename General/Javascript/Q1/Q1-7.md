# Q1-7: How do you handle form validation in React using Zod or similar tools?

- Zod is a TypeScript-first schema validation library.
- It validates form data and also infers types automatically.
- It’s fast, strict, and integrates well with form libraries like React Hook Form.

- Example – Standalone Zod Validation

```tsx
import { z } from 'zod';

const schema = z.object({
  email: z.string().email(),
  password: z.string().min(6),
});

const formData = {
  email: 'test@example.com',
  password: '123456',
};

const result = schema.safeParse(formData);

if (!result.success) {
  console.log(result.error.format());
}
```

- Using Zod with React Hook Form (best practice)

1. Install required packages:

```bash
npm install react-hook-form zod @hookform/resolvers
```

2. Define your schema and form:

```tsx
import { useForm } from 'react-hook-form';
import { z } from 'zod';
import { zodResolver } from '@hookform/resolvers/zod';

const loginSchema = z.object({
  email: z.string().email({ message: "Invalid email" }),
  password: z.string().min(6, { message: "Min 6 characters" }),
});

type LoginForm = z.infer<typeof loginSchema>;

export default function LoginForm() {
  const {
    register,
    handleSubmit,
    formState: { errors },
  } = useForm<LoginForm>({
    resolver: zodResolver(loginSchema),
  });

  const onSubmit = (data: LoginForm) => {
    console.log("Valid:", data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register("email")} placeholder="Email" />
      {errors.email && <p>{errors.email.message}</p>}

      <input {...register("password")} placeholder="Password" type="password" />
      {errors.password && <p>{errors.password.message}</p>}

      <button type="submit">Login</button>
    </form>
  );
}
```

- Advantages:

| Benefit    | Explanation                                                                    |
| ---------- | ------------------------------------------------------------------------------ |
| Type-safe  | Automatically infers TypeScript types from your schema                         |
| Reusable   | You can reuse schemas across client/server (e.g. API validation)               |
| Fast       | Lightweight and minimal overhead                                               |
| Composable | Easily nest or extend schemas (e.g. `userSchema.extend({ role: z.string() })`) |

- Common Mistakes:

| Mistake                      | Fix                                                   |
| ---------------------------- | ----------------------------------------------------- |
| Only validating in frontend  | Also validate on backend for security                 |
| Forgetting `.safeParse()`    | Use it instead of `.parse()` to avoid runtime crashes |
| Duplicating validation rules | Use Zod in both React and backend (e.g., API layer)   |
