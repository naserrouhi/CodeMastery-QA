# Q1-2: What are the differences between React and Next.js, and when would you use each?

| Feature           | React                                     | Next.js                                                                                               |
| ----------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Type              | Frontend library                          | Full-stack framework (built on React)                                                                 |
| Rendering         | CSR (Client-Side Rendering) only          | CSR, SSR (Server-Side Rendering), SSG (Static Site Generation), ISR (Incremental Static Regeneration) |
| Routing           | Manual with `react-router`                | File-based routing out-of-the-box                                                                     |
| Backend Support   | None (frontend only)                      | Supports backend functions (API routes)                                                               |
| Performance (SEO) | Lower (because of CSR)                    | Higher with SSR/SSG – good for SEO                                                                    |
| Configuration     | You configure everything (Webpack, Babel) | Zero-config to get started                                                                            |
| Deployment        | Any static hosting (Netlify, Vercel)      | Optimized for Vercel, but can run anywhere                                                            |

- When to Use React:

    - You want full control over the project setup and build tools.
    - Your app is mostly client-side (e.g. dashboards, internal tools).
    - SEO is not a priority.
    - You want a lightweight frontend only.

- When to Use Next.js:

    - You want better SEO (e.g. blogs, e-commerce, marketing sites).
    - You want faster performance out of the box.
    - You want to reduce boilerplate setup.
