# Q7-1: What are vector databases, and how are they used in AI applications?

- Vector databases are specialized databases designed to store, index, and search high-dimensional vectors — numerical representations of data like text, images, audio, or video.
- These vectors typically come from machine learning models like BERT, CLIP, or OpenAI embeddings and represent semantic meaning.

- Why Not Use Traditional Databases?

  - Relational or document databases (like PostgreSQL or MongoDB) are not optimized for high-dimensional similarity search (e.g., finding similar texts or images).
  - Vector DBs use specialized algorithms to solve:
    - k-Nearest Neighbor (k-NN) Search
    - Approximate Nearest Neighbor (ANN) Search (faster, scalable)

- Use Cases in AI:

| Use Case                             | Description                                                                                         |
| ------------------------------------ | --------------------------------------------------------------------------------------------------- |
| Semantic Search                      | Search documents/images/code based on meaning, not keywords. E.g., Google Search, ChatGPT Retrieval |
| RAG (Retrieval-Augmented Generation) | Fetch relevant facts to feed into LLMs during a prompt.                                             |
| Recommendation Systems               | Recommend items similar to user preferences or history.                                             |
| Image/Video Similarity Search        | Find visually similar media in a database.                                                          |
| Chatbots with Memory                 | Store previous conversations or facts as embeddings.                                                |
| Fraud Detection / Anomaly Detection  | Compare user behavior vectors to known patterns.                                                    |

- Popular Vector Databases:

| Name         | Features                                     |
| ------------ | -------------------------------------------- |
| Pinecone     | Fully managed, scalable, used for RAG        |
| Weaviate     | Open-source, hybrid search, GraphQL support  |
| FAISS (Meta) | Local, fast ANN, often embedded in apps      |
| Milvus       | Open-source, scalable, ANN engine            |
| Qdrant       | Open-source, filtering + vector search       |
| Chroma       | Simple, local use in prototyping (LangChain) |

- How They Work

  1. Convert Input to Embedding

      - e.g., "What is AI?" → `[0.123, 0.554, ..., 0.049]` (using OpenAI or SentenceTransformer)

  2. Store Vector with Metadata

      - `{ vector: [...], metadata: { id: 123, title: 'AI' } }`

  3. Query with a New Vector

     - Compare using cosine similarity, dot product, or Euclidean distance

- Example (with `Pinecone` or `FAISS`)

```js
// Pseudo-code with OpenAI + Pinecone
const embedding = await openai.createEmbedding("How to learn Node.js?");
pinecone.upsert({ id: "doc1", vector: embedding, metadata: { title: "Node Guide" } });

const queryVector = await openai.createEmbedding("Learning backend development");
const results = await pinecone.query({ vector: queryVector, topK: 3 });
```
