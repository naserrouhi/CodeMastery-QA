# Q4-1: Compare Mongoose schema validation with using Zod for API-level validation

| Validation Type     | Layer           | Purpose                                                 |
| ------------------- | --------------- | ------------------------------------------------------- |
| Mongoose Validation | Database Model  | Ensures data stored in MongoDB is valid                 |
| Zod Validation      | API/Input Layer | Validates data coming into your API (e.g. request body) |

- Mongoose Schema Validation

  - Example:

```js
const userSchema = new mongoose.Schema({
  name: { type: String, required: true, minlength: 3 },
  age: { type: Number, min: 0, max: 100 },
});

const User = mongoose.model('User', userSchema);
```

  - Pros:
    - Built into Mongoose
    - Validates automatically on `.save()` or `.create()`
    - Tied directly to database schema

  - Cons:
    - Can’t catch bad data before reaching the database
    - Can’t validate external inputs like query params or headers
    - Not composable or reusable across frontend/backend

- Zod Validation (API-Level)

  - Example:

```ts
const userSchema = z.object({
  name: z.string().min(3),
  age: z.number().min(0).max(100),
});

// In Express route
app.post('/users', (req, res) => {
  const result = userSchema.safeParse(req.body);
  if (!result.success) return res.status(400).json(result.error);
  // Proceed with creating user
});
```

  - Pros:
    - Validates before hitting DB
    - Works in both frontend and backend (universal schema)
    - Composable: you can create nested schemas
    - More expressive and type-safe with TypeScript

  - Cons:
    - Requires manual wiring into routes (not automatic like Mongoose)
    - Doesn’t protect DB layer — you still need Mongoose/schema validation to be safe

- Best Practice:

```paintext
Client Input --> Zod (API Validation) --> Mongoose (DB Validation)
```

  1. Use Zod to validate:
     - Request body
     - Query params
     - URL params

  2. Use Mongoose to:

     - Ensure data in DB remains valid
     - Catch edge cases (e.g. direct DB scripts or unexpected bugs)

| Feature                          | Mongoose | Zod                 |
| -------------------------------- | -------- | ------------------- |
| Scope                            | DB layer | API layer           |
| Reusable across frontend/backend | ❌       | ✅                 |
| TypeScript support               | Weak     | Strong              |
| Validates before DB hit          | ❌       | ✅                 |
| Use for DB inserts/updates       | ✅       | ❌ (use alongside) |
| Use for request/query validation | ❌       | ✅                 |
