# Q4-3: How do you handle migrations in MongoDB?

- In MongoDB, migrations are manual or tool-assisted scripts that update your schema or data as your application evolves.
- Since MongoDB is schema-less, schema migrations are not enforced, but data migrations (e.g., renaming fields, transforming documents) are still essential in production.

- Common Ways to Handle Migrations

  1. Manual Scripts

     - Write a simple Node.js script that connects to MongoDB and performs transformations.

     - Example (rename a field):

```js
const { MongoClient } = require("mongodb");

async function runMigration() {
  const client = new MongoClient("mongodb://localhost:27017");
  await client.connect();

  const db = client.db("yourDb");
  const users = db.collection("users");

  await users.updateMany(
    { fullName: { $exists: true } },
    { $rename: { "fullName": "name" } }
  );

  console.log("Migration complete");
  await client.close();
}

runMigration();
```

  2. Use a Migration Tool

     - Install:

```bash
npm install -g migrate-mongo
```

     - Workflow:

```bash
migrate-mongo init               # Initializes folder structure
migrate-mongo create add-index  # Creates a timestamped migration file
migrate-mongo up                # Runs pending migrations
```

     - Migration Example:

```js
// migrations/20230803123456-add-isActive.js
module.exports = {
  async up(db) {
    await db.collection("users").updateMany({}, { $set: { isActive: true } });
  },
  async down(db) {
    await db.collection("users").updateMany({}, { $unset: { isActive: "" } });
  }
};
```

  3. With Mongoose

     - If using Mongoose, run the logic in startup scripts or versioned cron jobs.

```js
// Check schema version and run upgrade logic
if (user.schemaVersion < 2) {
  user.email = user.contact.email;
  delete user.contact.email;
  user.schemaVersion = 2;
  await user.save();
}
```

| Tip                            | Why                                |
| ------------------------------ | ---------------------------------- |
| Back up your DB before running | Protect from accidental corruption |
| Run migrations in batches      | Avoid blocking large collections   |
| Use indexes where needed       | Improve performance                |
| Log each step                  | Debug easily                       |
| Run in staging first           | Catch errors before prod           |
