# Q4-2: How do you model relationships in MongoDB? Give examples of embedded vs referenced documents

1. Referenced Documents (Normalization)

   - Documents reference each other by storing the `_id` of related documents.

   - Use When:
     - Relationships are many-to-many or one-to-many
     - Related data is large, frequently updated, or shared
     - You want to avoid data duplication

   - Example:

```js
// users collection
{
  _id: ObjectId("user123"),
  name: "Alice"
}

// posts collection
{
  _id: ObjectId("post456"),
  title: "My Post",
  content: "Hello world",
  authorId: ObjectId("user123") // Reference to user
}
```

   - Fetching:
     - You’d use a second query or `$lookup` to join:

```js
db.posts.aggregate([
  {
    $lookup: {
      from: "users",
      localField: "authorId",
      foreignField: "_id",
      as: "author"
    }
  }
])
```

2. Embedded Documents (Denormalization)

   - You embed related documents directly inside a parent document.

   - Use When:
     - One-to-few or tightly coupled data
     - Data is always fetched together
     - Embedded data won’t change independently

   - Example:

```js
// orders collection
{
  _id: ObjectId("order789"),
  customerName: "John",
  items: [
    { productId: "apple123", quantity: 2 },
    { productId: "banana456", quantity: 1 }
  ]
}
```

   - Benefit:
     - One document = one read
     - Simpler code and faster reads

- Embedded vs Referenced Comparison

| Aspect            | Embedded                   | Referenced                    |
| ----------------- | -------------------------- | ----------------------------- |
| Read Performance  | Faster (1 read)            | Slower (2 queries / \$lookup) |
| Write Performance | Faster if few updates      | More complex writes           |
| Data Duplication  | Yes                        | Avoids duplication            |
| Data Consistency  | Harder to keep in sync     | Easier to update separately   |
| Use Case          | Blog comments, Order items | Users, Tags, Products         |

- Best Practice

  - Embed when: 1-to-1 or 1-to-few and the data is read together.
  - Reference when: many-to-many or when data is large/independent.
