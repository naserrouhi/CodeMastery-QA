# Q2-77: What is the difference between consistency and data safety?

- They are two important concepts in distributed systems and messaging platforms like RabbitMQ.

1. Consistency

    - It ensures that all nodes see the same data at the same time.

    - Key Aspects:
        
        - Strong Consistency: All nodes agree on the state of the data at all times. For example, if a message is written to one node, it is immediately visible to all other nodes.

        - Eventual Consistency: Nodes may temporarily have different views of the data, but they will eventually converge to the same state. This is common in systems that prioritize availability over consistency.

        - Read/Write Consistency: Ensures that a read operation returns the most recent write. For example, if a consumer reads a message, it should see the latest version of that message.

    - RabbitMQ:
        
        - In quorum queues, strong consistency is achieved using the Raft consensus algorithm. All replicas agree on the state of the queue, ensuring that messages are processed in the correct order and no duplicates are created.

        - In classic queues, consistency is weaker because replication is asynchronous, and replicas may temporarily be out of sync with the primary node.

2. Data Safety

    - It ensures that data is not lost or corrupted, even if a node crashes, a network issue occurs, or other failures happen.

    - Key Aspects:

        - Durability: Data is written to disk and survives node failures.

        - Replication: Data is copied to multiple nodes to ensure it is not lost if one node fails.

        - Atomicity: Operations are atomic, meaning they either complete fully or not at all. Partial updates are not allowed.

    - RabbitMQ:

        - In quorum queues, data safety is ensured by synchronously replicating messages to a majority of nodes before acknowledging the write.

        - In classic queues, data safety is weaker because replication is asynchronous. If the primary node fails before a message is replicated, the message may be lost.


In RabbitMQ:
- **Quorum queues** provide both strong consistency and data safety.
- **Classic queues** offer weaker guarantees for both, making them less suitable for critical workloads.
- **Stream queues** prioritize high throughput and sequential access, with strong data safety but less focus on consistency across consumers.
