# Q2-75: What are RabbitMQ Mirroring and Standalone?

1. Standalone

    - A single RabbitMQ broker (server) running independently.
    - Pros: Simple, easy to set up.
    - Cons: No high availability (HA). If the server crashes, messages and queues are lost.

2. Mirrored Queues (HA Queues)

    - Queues are replicated across multiple nodes in a cluster.
    - If the master node (primary queue) fails, a mirror (replica) automatically takes over.
    - Ensures high availability and prevents message loss.

- Node

    - It is a single instance of a RabbitMQ server.
    
    - Each node in a RabbitMQ system has its own queues, exchanges, and bindings.

- Cluster

    - It is a group of RabbitMQ nodes that work together to share resources and provide high availability.

    - Queues can be mirrored across multiple nodes for fault tolerance (e.g., if one node fails, the message is still available from another node).

    - The cluster helps in load balancing and improving the scalability of RabbitMQ systems.
