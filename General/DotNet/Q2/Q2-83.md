# Q2-83: Explain messaging patterns in RabbitMQ

- They define how messages are exchanged between producers and consumers.

1. Point-to-Point (P2P) / Work Queue

    - Distributing tasks among multiple workers (e.g., background job processing).

    - Steps:

        1. A producer sends messages to a queue.
        2. A single consumer (worker) processes each message.
        3. If multiple consumers are connected, RabbitMQ distributes messages among them (round-robin).

    - Queue Type: Classic / Quorum

    - Exchange Type: Direct (or default exchange)

2. Publish-Subscribe (Pub/Sub) / Event-Driven Messaging

    - Broadcasting messages to multiple consumers (e.g., sending notifications to different services).

    - Steps:

        1. A producer sends messages to an exchange (Fanout or Topic exchange).
        2. The exchange forwards the message to multiple queues.
        3. All consumers bound to those queues receive a copy of the message.

    - Queue Type: Classic / Quorum / Stream

    - Exchange Type: Fanout / Topic

3. Request-Response (RPC)

    - When a client needs a reply after sending a request (e.g., microservices communication).

    - Steps:

        1. The producer (client) sends a request message to a queue.
        2. A consumer (server) processes it and sends back a response message to a reply queue.
        3. The client listens for the response.

    - Queue Type: Classic / Quorum

    - Exchange Type: Direct

4. Routing (Direct Messaging)

    - Sending messages to specific consumers based on a key (e.g., routing logs based on severity: ERROR, INFO).

    - Steps:

        1. A producer sends messages with a routing key.
        2. The exchange sends the message only to queues that match the routing key.

    - Queue Type: Classic / Quorum

    - Exchange Type: Direct

5. Topic-Based Messaging

    - Filtering messages based on patterns (e.g., logging different application modules).

    - Steps:

        1. A producer sends messages with a routing key like logs.error.app1.
        2. Consumers subscribe using wildcards.

    - Queue Type: Classic / Quorum

    - Exchange Type: Topic

6. Fanout Messaging

    - Broadcasting messages to all consumers (e.g., real-time updates, chat notifications).

    - Steps:

        1. A producer sends a message to an exchange.
        2. The exchange forwards it to all bound queues, regardless of routing keys.

    - Queue Type: Classic / Quorum / Stream

    - Exchange Type: Fanout

7. Dead Letter Queue (DLQ)

    - Handling messages that fail to process (e.g., rejected messages, expired TTL).

    - Steps:

        1. Messages that are rejected, expired, or exceeded retry attempts are sent to a dead-letter queue for further processing.

    - Queue Type: Classic / Quorum

    - Exchange Type: Direct / Any

8. Streaming Messaging (Event Sourcing)

    - Keeping message history and replaying events (e.g., financial transactions, analytics).

    - Steps:

        1. A producer sends messages to a stream queue.
        2. Consumers can replay old messages or process them in real-time.

    - Queue Type: Stream

    - Exchange Type: Direct / Topic / Fanout
