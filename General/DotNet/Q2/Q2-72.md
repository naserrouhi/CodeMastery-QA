# Q2-72: Why should we use DLX to retry When we can retry directly in the main queue?

1. Supports Delayed Retries (Using TTL)

    - If you retry directly, retries happen immediately, which can cause rapid failures if an external service (e.g., a database) is temporarily down.

2. Prevents Infinite Retry Loops

3. Helps with Monitoring and Debugging

- Example of delayed Retry:

    1. Create a DLX Queue with TTL

```csharp
var retryArgs = new Dictionary<string, object>
{
    { "x-message-ttl", 5000 }, //Message waits 5 seconds before retrying
    { "x-dead-letter-exchange", "main_exchange" }, //Send back to main queue
    { "x-dead-letter-routing-key", "main_routing_key" }
};

channel.QueueDeclare("retry_queue", true, false, false, retryArgs);
```

    2. Set Main Queue to Use DLX for Retries

```csharp
var mainQueueArgs = new Dictionary<string, object>
{
    { "x-dead-letter-exchange", "retry_exchange" }, //Send failed messages to retry queue
    { "x-dead-letter-routing-key", "retry_routing_key" }
};

channel.QueueDeclare("main_queue", true, false, false, mainQueueArgs);
```

Now, if a message fails, it moves to retry_queue, waits 5 seconds, and then comes back to the main queue.
