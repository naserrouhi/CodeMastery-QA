## Q2-4: Explain types of programming diagram.

1. Imperative Programming

    - The program describes how to do something using step-by-step instructions.
    - Uses variables, loops, and conditionals to modify the program state.
    - Pros: Clear control flow
    - Cons: More complex for large systems

```csharp
var sum = 0;

for (var i = 1; i <= 5; i++)
    sum += i;

Console.WriteLine(sum);
```


2. Procedural Programming
    
    - A subset of imperative programming.
    - Breaks down a program into reusable functions (procedures).
    - Pros: Simple and easy to understand
    - Cons: Not scalable for large applications

```csharp
public class Calculator
{
    public static int Add(int a, int b) => a + b;
    public static int Subtract(int a, int b) => a - b;
}

Console.WriteLine(Calculator.Add(5, 3));
```


3. Object-Oriented Programming
    
    - Organizes code into objects with data and behaviors.
    - Objects represent real-world entities
    - Pros: Code reusability, modular design
    - Cons: Can be complex for simple tasks

```csharp
public class Car
{
    public string Brand { get; set; }
    public void Drive() => Console.WriteLine($"{Brand} is driving.");
}

var myCar = new Car { Brand = "Toyota" };
myCar.Drive();
```

4. Functional Programming
    
    - Focuses on pure functions, immutability, and avoiding side effects.
    - Pros: Less side effects, easier to debug
    - Cons: Not intuitive for OOP-based developers.

```csharp
var numbers = new List<int> { 1, 2, 3, 4, 5 };
var squaredNumbers = numbers.Select(n => n * n);

Console.WriteLine(string.Join(", ", squaredNumbers));
```


5. Declarative Programming
    
        - Focuses on what to do, not how to do it.
        - Uses expressions and rules instead of explicit step-by-step instructions.
        - Example: SQL Queries where you declare the data you need.
        - Pros: Less code, easier to read
        - Cons: Less control over execution

```csharp
var numbers = new List<int> { 1, 2, 3, 4, 5 };
var evenNumbers = numbers.Where(n => n % 2 == 0); 

Console.WriteLine(string.Join(", ", evenNumbers));
```


6. Event-Driven Programming

    - The flow is determined by events like user actions or system signals.
    - Components react to events instead of executing sequentially.
    - Pros: Decouples components, improves responsiveness.
    - Cons: Harder to debug due to unpredictable execution order.

```csharp
public class ButtonClickExample
{
    public event Action ButtonClicked;

    public void ClickButton()
    {
        ButtonClicked?.Invoke();
    }
}

var button = new ButtonClickExample();
button.ButtonClicked += () => Console.WriteLine("Button was clicked!");
button.ClickButton();
```


7. Asynchronous Programming

    - Code execution doesn't block waiting for operations to complete.
    - Uses async/await, callbacks, or promises to handle tasks efficiently.
    - Pros: Improves performance and responsiveness.
    - Cons: Can be complex due to callback chains or race conditions.

```csharp
public async Task DownloadFileAsync()
{
    Console.WriteLine("Downloading file...");
    await Task.Delay(2000);
    Console.WriteLine("Download complete!");
}

await DownloadFileAsync();
```


8. Generic Programming

    - Allows writing reusable code that works with any data type.
    - Uses generics (T).
    - Pros: Promotes code reuse and maintainability.
    - Cons: Can increase compilation complexity and readability issues.

```csharp
public class Box<T>
{
    public T Item { get; set; }
}

var intBox = new Box<int> { Item = 42 };
var stringBox = new Box<string> { Item = "Hello" };

Console.WriteLine(intBox.Item);
Console.WriteLine(stringBox.Item);
```


9. Logic Programming

    - Uses rules and facts to derive conclusions.
    - Uses if-then rules and pattern matching.
    - Example: AI chatbots where logic is used to determine responses.
    - Pros: Great for knowledge-based systems and AI.
    - Cons: Limited control over execution flow, not suited for all problems.


10. Metaprogramming

    - Code that generates or modifies other code at runtime or compile-time.
    - Enables dynamic behaviors and reflection.
    - Pros: Increases flexibility, reduces repetitive code.
    - Cons: Can be hard to debug and impacts performance.

```csharp
Type type = typeof(string);
Console.WriteLine(type.FullName);
```


11. Reactive Programming

    - Programs react to data changes and events asynchronously.
    - Instead of manually pulling data or handling updates, your program responds automatically when data changes.
    - In C#, Rx.NET is commonly used for reactive programming.
    - Example: Stock market app: Updates prices automatically when they change.
    - Pros: Handles complex event-driven scenarios efficiently.
    - Cons: Steep learning curve, potential memory leaks with unhandled subscriptions.

    - Key Concepts:
        - Streams: Continuous flow of data/events (like a river).
        - Observers: Functions that listen to and react to data changes.
        - Schedulers: Manage concurrency and execution order.
        - Backpressure: Controls data flow to prevent overwhelming consumers.

```csharp
using System;
using System.Reactive.Linq;

class Program
{
    static void Main()
    {
        var observable = Observable.Interval(TimeSpan.FromSeconds(1))
                                   .Take(5);
        
        observable.Subscribe(value => Console.WriteLine($"Received: {value}"));

        Console.ReadLine();
    }
}
```


12. Message-Driven Programming

    - Components communicate via messages instead of direct method calls.
    - It is commonly used in distributed systems, microservices, and event-driven architectures.
    - Improves decoupling in distributed systems.
    - It uses Message Brokers.
    - Pros: Scales well, enables fault-tolerant systems.
    - Cons: Requires message handling infrastructure, potential delays in processing.

```csharp
public class OrderRequest : IRequest<string>
{
    public string Food { get; set; }
    public OrderRequest(string food) => Food = food;
}

public class OrderHandler : IRequestHandler<OrderRequest, string>
{
    public Task<string> Handle(OrderRequest request, CancellationToken cancellationToken)
    {
        return Task.FromResult($"Order received: {request.Food}");
    }
}

class Program
{
    static async Task Main()
    {
        var mediator = new Mediator(type => Activator.CreateInstance(type));
        var response = await mediator.Send(new OrderRequest("Pizza"));
        
        Console.WriteLine(response);
    }
}
```
