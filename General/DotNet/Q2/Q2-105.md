# Q2-105: What are LDAP and Kerberos?

- They are two protocols commonly used in AD for authentication and directory access.

1. LDAP (Lightweight Directory Access Protocol)

    - A protocol used to query and modify directory services (like Active Directory).
    - Helps retrieve user details, groups, and permissions from AD.
    - Works over TCP/IP (port 389 for unencrypted, 636 for encrypted/LDAPS).
    - Used for authentication and user lookup but does not handle secure authentication by itself.
    - Example: A web application queries AD to check if a username exists.

2. Kerberos

    - A secure authentication protocol that provides SSO.
    - Uses tickets to verify identities without sending passwords over the network.
    - Works on port 88.
    - More secure than LDAP alone because passwords are never sent over the network.
    - Example: A user logs into a corporate laptop and gets a Kerberos ticket, which allows access to shared folders and apps without needing to log in again.

- Kerberos Ticket:

    - It is like a temporary digital pass that allows a user or system to access services securely without repeatedly entering credentials.

    1. The user enters their credentials, which are verified by the Key Distribution Center (KDC).

    2. If the credentials are correct, the KDC issues a TGT (Ticket Granting Ticket), which proves the user is authenticated. This ticket has an expiration time.

    3. When the user wants to access a specific service, they request a service ticket from the KDC using the TGT.

    4. The service ticket is presented to the requested service, and if valid, access is granted without needing to re-enter credentials.

    - The user does need to enter their password once when they first log in. But after that, Kerberos eliminates the need to send the password over the network repeatedly.
