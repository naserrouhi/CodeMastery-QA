# Q2-44: What's Checksum?



---


- Checksum:

    - It is used to detect errors in the transmitted data (both the header and payload).

It works by calculating a value based on the packet contents and checking it at the receiving end.

If the checksum value at the receiver side doesn’t match, the packet is discarded and re-transmitted.


🔹 How It Works:
The sender calculates the checksum by adding up all the data in the packet and taking the two’s complement of the result. The receiver does the same check to ensure the data hasn’t been corrupted during transmission.

2️⃣ How Does the Checksum Work?

The checksum is a mechanism used to detect errors in the data during transmission. It helps ensure the integrity of the transmitted data by comparing a computed value between the sender and receiver.

Here’s how it works:

1. Sender Side:

The sender takes the TCP segment (which includes both header and payload) and performs a checksum calculation.

The checksum is calculated by taking the binary sum of all the segments (header + payload). If the sum exceeds the size of the data field, the result is wrapped around, and the two's complement is calculated.

The result (checksum value) is placed in the checksum field in the TCP header.



2. Receiver Side:

The receiver computes the checksum in the same way using the received segment (header + payload).

If the checksum value calculated by the receiver matches the checksum value sent by the sender, the data is assumed to be intact.

If the values don’t match, the packet is considered corrupted, and the receiver will discard it and request retransmission.





---

Example of Checksum Calculation:

1. Sender Side:

Let's assume the data to be transmitted is:

Data: "Hello"

First, we convert each byte of data into binary:


H = 72 (01001000)
e = 101 (01100101)
l = 108 (01101100)
l = 108 (01101100)
o = 111 (01101111)

Now, add these numbers together (in binary):


01001000
+ 01100101
+ 01101100
+ 01101100
+ 01101111
-------------
  11110100 (total sum)

We add the carry (if any) and wrap it around (if necessary) to ensure the sum fits in a 16-bit field, then we take the two’s complement to get the checksum.


2. Receiver Side:

The receiver will take the received data and compute the checksum in the same way.

It will then compare the result with the checksum value received in the header.

If the checksum matches, the data is correct, otherwise, the packet is discarded and a retransmission is requested.



---

Visualizing the Process:

If the sum of the receiver's checksum matches the sender's checksum, the data is accepted; otherwise, it will be discarded, and the receiver will request a retransmission.
