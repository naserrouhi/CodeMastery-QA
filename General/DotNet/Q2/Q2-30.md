# Q2-30: Which communication types does RabbitMQ supports?

1. RPC (Request-Response Pattern)

    - Used for direct communication between a client and a server.
    - The client sends a request message and waits for a reply message.
    - Example: A microservice calls another microservice to get customer data.

2. Event-Driven Messaging (Pub/Sub)

    - Used when multiple consumers need to receive messages.
    - The producer does not wait for a response.
    - One producer, publishes a message to an exhange, multiple consumers consume it.
    - Example: A user signs up → Multiple services (email, analytics, notifications) get the event.

3. Work Queue (Task Queue)

    - Used for distributing work across multiple workers.
    - A producer sends tasks to a queue.
    - Workers (consumers) process the tasks.
    - Each message is processed by only one worker.
    - Example: A website processes images in the background.

4. Direct Messaging

    - A producer sends a message to a specific queue using a routing key.
    - Only the consumer(s) listening to that specific queue receive the message.
    - Example: A system sends error logs to an "error" queue and info logs to an "info" queue.

5. Topic-Based Messaging

    - Used when messages should go to different queues based on patterns.
    - Uses routing keys with wildcards.
    - Example:
        - Logs are published with routing keys like logs.error, logs.info.
        - Consumers subscribe to logs.* to receive all logs, or logs.error for only error logs.

6. Fanout Messaging

    - Used to broadcast messages to all consumers.
    - Messages are sent to an Exchange, which sends them to all bound queues.
    - All consumers receive the same message.
    - Example: A news system sends breaking news to all subscribers.

7. Dead Letter Queue (DLQ)

    - A special queue for messages that fail to process.
    - Used to handle errors and retries.
    - Example: A payment system retries failed transactions.
