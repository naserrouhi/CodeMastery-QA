# Q2-38: What is a TCP connection?

Http? Https? FTP? SMTP? SSH?

- A TCP (Transmission Control Protocol) connection is a communication between two devices (client and server) over a network.

- Key Features:

  - Reliable: Ensures data is delivered without loss.
  - Ordered: Maintains correct sequence of messages.
  - Error-Checked: Detects and resends lost or corrupted packets.
  - Full-Duplex: Both sides can send and receive data at the same time.

- Use Cases:
  - Web browsing (HTTP/HTTPS)
  - File transfers (FTP)
  - Emails (SMTP)
  - Remote access (SSH)

- Steps:

    1. Connection Establishment (Three-Way Handshake)

    2. Data Transmission

        - Data is divided into packets, and each packet is assigned a sequence number.
        - The receiver sends ACK messages to confirm packet receipt.
        - If a packet is lost or arrives out of order, TCP resends the missing packet.

    3. Connection Termination (Four-Way Handshake)

        - Client → FIN → Server → Client sends FIN (Finish) to close its side.
        - Server → ACK → Client → Server acknowledges the request.
        - Server → FIN → Client → Server sends FIN to close its side.
        - Client → ACK → Server → Client acknowledges, and the connection closes.

- Handling Packet Loss (Retransmission Example):

    1. Client sends "H" (1000), "E" (1001), "L" (1002), "L" (1003), "O" (1004).

    2. Server receives "H" (1000), "E" (1001), "L" (1003), "O" (1004) – but "L" (1002) is missing.

    3. Server does not send ACK 1003, instead, it requests missing packet 1002.

    4. Client retransmits "L" (1002), and server acknowledges it (ACK 1003).
  
- Timeout:

  - If the sender does not receive an acknowledgment within the timeout period, it retransmits the data.

  - It is typically based on the estimated Round Trip Time (RTT), which is the time taken for a packet to travel from the sender to the receiver and back.

  - The timeout can adjust dynamically depending on network conditions and the observed RTT.
