# Q3-2: What is SRP?

- Definition:

    - A class should have only one reason to change.
    - Each class should do one thing and do it well.
    - If a class is doing multiple jobs, it becomes harder to understand, test, modify, and reuse.
    - SRP helps keep your classes clean, focused, and easier to maintain.
    - Example: A class that handles database access should not also handle logging.

- Bad Design: Changes in one area (e.g., how emails are sent) might break unrelated areas.

```csharp
public class Invoice
{
    public void CalculateTotal() {}

    public void SaveToDatabase() {}

    public void GeneratePDF() {}

    public void SendEmail() {}
}
```

- Good Design:

```csharp
public class Invoice
{
    public void CalculateTotal() {}
}

public class InvoiceRepository
{
    public void Save(Invoice invoice) {}
}

public class InvoicePdfGenerator
{
    public void Generate(Invoice invoice) {}
}

public class EmailService
{
    public void SendInvoice(Invoice invoice) {}
}
```

- Benefits:

    - Each class has one reason to change.
    - Easier to test (e.g., test InvoicePdfGenerator independently).
    - Easier to maintain and extend.
