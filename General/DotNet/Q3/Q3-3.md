# Q3-3: What is OCP?

- Definition:

    - Software entities (classes, modules, functions) should be open for extension, but closed for modification.
    - You should be able to add new behavior without changing existing code.
    - "Open for extension" → You should be able to add new behavior.
    - "Closed for modification" → You should not change existing code to add that behavior.
    - This helps avoid breaking existing code and makes your system more stable and extensible.
    - Use interfaces, abstractions, and inheritance to achieve this.

- Real-World Analogy:

    - Imagine a payment system in a shopping app.
    - Initially, it only supports Credit Card.
    - Later, you want to add PayPal, then UPI.
    - Instead of changing the original payment logic every time (which is risky), you extend it using new classes.

- Bad Design:

```csharp
public class PaymentProcessor
{
    public void Process(string paymentType)
    {
        if (paymentType == "CreditCard") {}
        else if (paymentType == "PayPal") {}
        else if (paymentType == "UPI") {}
    }
}
```

- Problems:

    - You have to modify this class every time you add a new payment type.
    - Easy to introduce bugs.

- Good Design: Use polymorphism and interfaces to make it extensible.

```csharp
public interface IPaymentMethod
{
    void Pay();
}

public class CreditCardPayment : IPaymentMethod
{
    public void Pay()
    {
        Console.WriteLine("Paid using Credit Card");
    }
}

public class PayPalPayment : IPaymentMethod
{
    public void Pay()
    {
        Console.WriteLine("Paid using PayPal");
    }
}

public class PaymentProcessor
{
    public void Process(IPaymentMethod paymentMethod)
    {
        paymentMethod.Pay(); // No need to change this method when adding new types
    }
}

var processor = new PaymentProcessor();
processor.Process(new CreditCardPayment());
processor.Process(new PayPalPayment());
```

- Benefits:

    - You can add new payment types without touching PaymentProcessor.
    - Easy to test and extend.

- Combine with DI:

```csharp
public interface IPaymentMethod
{
    string Name { get; }
    void Pay(decimal amount);
}

public class CreditCardPayment : IPaymentMethod
{
    public string Name => "CreditCard";

    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount:C} using Credit Card.");
    }
}

public class PayPalPayment : IPaymentMethod
{
    public string Name => "PayPal";

    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount:C} using PayPal.");
    }
}

public interface IPaymentFactory
{
    IPaymentMethod GetPaymentMethod(string name);
}

public class PaymentFactory : IPaymentFactory
{
    private readonly IEnumerable<IPaymentMethod> _paymentMethods;

    public PaymentFactory(IEnumerable<IPaymentMethod> paymentMethods)
    {
        _paymentMethods = paymentMethods;
    }

    public IPaymentMethod GetPaymentMethod(string name)
    {
        var method = _paymentMethods.FirstOrDefault(p => p.Name.Equals(name, StringComparison.OrdinalIgnoreCase));
        return method ?? throw new ArgumentException("Invalid payment method.");
    }
}

public class PaymentProcessor
{
    private readonly IPaymentFactory _paymentFactory;

    public PaymentProcessor(IPaymentFactory paymentFactory)
    {
        _paymentFactory = paymentFactory;
    }

    public void ProcessPayment(decimal amount, string methodName)
    {
        var method = _paymentFactory.GetPaymentMethod(methodName);
        method.Pay(amount);
    }
}
```

```csharp
builder.Services.AddScoped<IPaymentMethod, CreditCardPayment>();
builder.Services.AddScoped<IPaymentMethod, PayPalPayment>();

builder.Services.AddSingleton<IPaymentFactory, PaymentFactory>();
builder.Services.AddScoped<PaymentProcessor>();
```
