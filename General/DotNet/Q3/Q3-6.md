# Q3-6: What is DIP?

- Definition:

  - High-level modules should not depend on low-level modules. Both should depend on abstractions.
  - Abstractions should not depend on details. Details should depend on abstractions.
  - This decouples your system and makes it easier to extend, test, and maintain.
  - Use interfaces or abstract classes to reduce direct dependencies.
  - Helps with testing and swapping implementations.

- Bad Design:

  - PaymentProcessor is tightly coupled to CreditCardPayment.
  - If you want to change to PayPal or test with a fake class, you have to modify the processor.

```csharp
public class PaymentProcessor
{
    private readonly CreditCardPayment _creditCardPayment;

    public PaymentProcessor()
    {
        _creditCardPayment = new CreditCardPayment();
    }

    public void ProcessPayment(decimal amount)
    {
        _creditCardPayment.Pay(amount);
    }
}
```

- Good Design:

  - Depend on abstractions (IPaymentMethod)
  - Use constructor injection (or DI container)
  - You can inject any implementation of IPaymentMethod (CreditCard, PayPal, Mock for testing).
  - Your PaymentProcessor doesn’t care how the payment is made.
  - It depends on abstraction, not a concrete detail.

```csharp
public interface IPaymentMethod
{
    void Pay(decimal amount);
}

public class CreditCardPayment : IPaymentMethod
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount:C} using Credit Card.");
    }
}

public class PayPalPayment : IPaymentMethod
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount:C} using PayPal.");
    }
}
```

- Now the high-level module:

```csharp
public class PaymentProcessor
{
    private readonly IPaymentMethod _paymentMethod;

    public PaymentProcessor(IPaymentMethod paymentMethod)
    {
        _paymentMethod = paymentMethod;
    }

    public void ProcessPayment(decimal amount)
    {
        _paymentMethod.Pay(amount);
    }
}
```
