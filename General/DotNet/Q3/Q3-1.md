# Q3-1: What is SOLID?

- SOLID is an acronym for five design principles that help make software more understandable, flexible, and maintainable.

    - Single Responsibility Principle (SRP)
    - Open/Closed Principle (OCP)

- Liskov Substitution Principle (LSP)

    - Objects of a base class should be replaceable with objects of a derived class without breaking the application.
    - A subclass should behave in a way that doesn't surprise or break the expectations of code using the base class.
    - Violating this usually causes runtime bugs.

- Interface Segregation Principle (ISP)

    - Clients should not be forced to depend on interfaces they do not use.
    - Split large interfaces into smaller, specific ones.
    - Helps keep the code clean and focused.

- Dependency Inversion Principle (DIP)

    - High-level modules should not depend on low-level modules. Both should depend on abstractions.
    - Use interfaces or abstract classes to reduce direct dependencies.
    - Helps with testing and swapping implementations.
