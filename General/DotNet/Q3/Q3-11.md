# Q3-11: What are the DI lifetimes?

1. Singleton

    - The same instance is shared for the entire life of the application.
    - It’s created once and reused everywhere.
    - Be careful with state in singletons — they're shared across all users and threads.
    - For background services (IHostedService), use singleton (they're created at startup).
    - Use cases: Configuration providers, Caching services, Logger instances, Stateless services used by all requests (e.g., encryption helpers, utility formatters)

2. Scoped

    - One instance per request (HTTP request).
    - Shared within a request, but not shared across requests.
    - This is the most commonly used lifetime for services that work with EF Core DbContext or anything request-specific.
    - Use cases: EF Core DbContext, Business services that depend on DbContext, Unit of Work or Repository pattern services, Request-level state (user permissions, localization)

3. Transient

    - A new instance is created every time it is requested (even within the same request).
    - Good for lightweight, stateless services — but not for expensive or shared resources.
    - Use cases: Lightweight, Stateless services (string formatter, date/time converter), Adapters or helpers (PdfGenerator, ImageResizer), Disposable objects

- Can you inject a scoped service into a singleton?
  
  - No — that causes a runtime error.
  - A singleton lives forever, but scoped services live only during requests.
  - To fix this, you use a factory or IServiceProvider to resolve the scoped service when needed.

```csharp
builder.Services.AddScoped<IEmailSender, EmailSender>();
builder.Services.AddSingleton<NotificationManager>();

public class NotificationManager
{
    private readonly IServiceProvider _provider;

    public NotificationManager(IServiceProvider provider)
    {
        _provider = provider;
    }

    public void Notify(string message)
    {
        using var scope = _provider.CreateScope();
        var emailSender = scope.ServiceProvider.GetRequiredService<IEmailSender>();
        emailSender.Send(message);
    }
}
```

```csharp
public interface IEmailSenderFactory
{
    IEmailSender Create();
}

public class EmailSenderFactory : IEmailSenderFactory
{
    private readonly IServiceProvider _provider;

    public EmailSenderFactory(IServiceProvider provider)
    {
        _provider = provider;
    }

    public IEmailSender Create()
    {
        return _provider.CreateScope().ServiceProvider.GetRequiredService<IEmailSender>();
    }
}

public class NotificationManager
{
    private readonly IEmailSenderFactory _factory;

    public NotificationManager(IEmailSenderFactory factory)
    {
        _factory = factory;
    }

    public void Notify(string message)
    {
        var sender = _factory.Create();
        sender.Send(message);
    }
}
```

- What happens if you inject a transient service into a scoped service?

  - It works fine.
  - A new instance is created every time it's needed inside that scoped service.

- What lifetime should I use for a DbContext?
  
  - Always scoped.
  - One context per request ensures safe tracking and consistency.

- What lifetime is best for a logger?

  - Singleton is fine — most logging services (like ILogger<T>) are thread-safe and designed to be reused.

- Can a singleton depend on transient?

  - It can depend on transient.
