# Q3-4: What is LSP?

- Definition:

  - A subclass should behave in a way that doesn't surprise or break the expectations of code using the base class.
  - In other words, if S is a subtype of T, then objects of type T may be replaced with objects of type S without breaking the application.
  - It ensures that derived classes extend the base class without changing its behavior.
  - Violating this usually causes runtime bugs.

- Bad Design:

```csharp
public class BlockedPayment : IPaymentMethod
{
    public string Name => "Blocked";

    public void Pay(decimal amount)
    {
        throw new NotSupportedException("This payment method is disabled.");
    }
}

paymentProcessor.ProcessPayment(100, "Blocked");
```

- Problems:

  - Consumers of the interface should not need to know or care about the concrete implementation.

- Good Design:

  - All implementations of IPaymentMethod should behave in a way that respects what the interface promises.

```csharp
public class CryptoPayment : IPaymentMethod
{
    public string Name => "Crypto";

    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount:C} using Cryptocurrency.");
    }
}
```
