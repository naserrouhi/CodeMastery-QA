# Q6-1: What is MVC?

- MVC is the simplest and most widely used pattern in ASP.NET applications.
- It separates concerns: UI, logic, input.
- The Model in MVC is not just data objects, it includes all business logic and data access.

| Layer      | Role                | What it Contains                               |
| ---------- | ------------------- | ---------------------------------------------- |
| Model      | Business/Data logic | Entities, Services, Repositories               |
| View       | Presentation        | Razor Pages, HTML, CSS                         |
| Controller | Request handling    | Input validation, Redirects, Calls to services |

- Where to Use It?

  - Small to medium web applications
  - Quick development
  - When you don’t need strict layering or domain-driven complexity

- Example:

| Component                            | Layer      | Responsibility                           |
| ------------------------------------ | ---------- | ---------------------------------------- |
| `Book` class                         | Model      | Holds data (Entity)                      |
| `IBookRepository` + `BookRepository` | Model      | Data access (e.g., DB)                   |
| `BookService`                        | Model      | Business logic (e.g., validation, rules) |
| `BookController`                     | Controller | Handles HTTP requests, calls services    |
| `Book View (.cshtml)`                | View       | Displays UI to user                      |

```csharp
// MODEL
public class Post {
    public int Id { get; set; }
    public string Title { get; set; }
    public string Content { get; set; }
}

// CONTROLLER
public class PostController : Controller {
    private readonly IPostService _postService;

    public PostController(IPostService postService) {
        _postService = postService;
    }

    public IActionResult Details(int id) {
        var post = _postService.GetPostById(id);
        return View(post);
    }
}

// VIEW (Details.cshtml)
@model Post

<h1>@Model.Title</h1>
<p>@Model.Content</p>
```

- Questions:

| Question                                                     | Sample Answer / Tip                                    |
| ------------------------------------------------------------ | ------------------------------------------------------ |
| What is ViewBag/ViewData/TempData?                           | They pass data from controller to view (short-lived).  |
| What’s the difference between PartialView and ViewComponent? | ViewComponent is reusable, testable and more powerful. |
| How do you validate models?                                  | Use `[Required]`, `ModelState.IsValid`.                |

- Common Mistakes:

| Mistake                          | How to Fix                                   |
| -------------------------------- | -------------------------------------------- |
| Fat controllers                  | Move logic to services                       |
| Mixing data access in controller | Use repository or service layer              |
| View too complex                 | Move logic to ViewModel or use ViewComponent |

- When to move beyond MVC?

  - If your application grows:
    - Becomes hard to test
    - Business rules spread everywhere
    - Need better separation or scalability
