# Q6-1: What is MVC?

- MVC is the simplest and most widely used pattern in ASP.NET applications.
- It separates concerns: UI, logic, input.
- It separates your app into 3 layers:

| Layer      | Responsibility                                            |
| ---------- | --------------------------------------------------------- |
| Model      | Business logic and data                                   |
| View       | UI (HTML, Razor)                                          |
| Controller | Handles user input and coordinates between View and Model |

- Where to Use It?

  - Small to medium web applications
  - Quick development
  - When you don’t need strict layering or domain-driven complexity

- Example:

Controllers/
    UserController.cs
Models/
    User.cs
Views/
    User/
        Index.cshtml

```csharp
// Model
public class User
{
    public string Name { get; set; }
    public int Age { get; set; }
}

// Controller
public class UserController : Controller
{
    public IActionResult Index()
    {
        var user = new User { Name = "Ali", Age = 30 };
        return View(user);
    }
}

// View (Index.cshtml)
@model User
<h1>@Model.Name - @Model.Age</h1>
```

- Questions:

| Question                                                     | Sample Answer / Tip                                    |
| ------------------------------------------------------------ | ------------------------------------------------------ |
| What is ViewBag/ViewData/TempData?                           | They pass data from controller to view (short-lived).  |
| What’s the difference between PartialView and ViewComponent? | ViewComponent is reusable, testable and more powerful. |
| How do you validate models?                                  | Use `[Required]`, `ModelState.IsValid`.                |

- Common Mistakes:

| Mistake                          | How to Fix                                   |
| -------------------------------- | -------------------------------------------- |
| Fat controllers                  | Move logic to services                       |
| Mixing data access in controller | Use repository or service layer              |
| View too complex                 | Move logic to ViewModel or use ViewComponent |

- When to move beyond MVC?

  - If your application grows:
    - Becomes hard to test
    - Business rules spread everywhere
    - Need better separation or scalability
