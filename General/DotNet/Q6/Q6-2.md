# Q6-2: What is N-Layer?

- N-Layer architecture (aka 3-Tier architecture) separates your application into logical layers, each with its own responsibility.
- It’s a natural upgrade to MVC when the app gets bigger and needs maintainability.

- Typical Layers:

| Layer                          | Description                              |
| ------------------------------ | ---------------------------------------- |
| Presentation Layer             | UI / Controllers / Razor views or APIs   |
| Business Layer (Service Layer) | Business logic and rules                 |
| Data Access Layer (DAL)        | Talks to the database (EF, Dapper, etc.) |
| (Optional: Domain Layer)       | Holds core models and interfaces         |

- Folder Structure:

MyApp/
├── MyApp.Web          => UI (ASP.NET MVC or API)
├── MyApp.Services     => Business logic
├── MyApp.Data         => Repositories, DbContext
├── MyApp.Domain       => Entities, DTOs, Interfaces

- Example:

```csharp
// Controller (Presentation)
public class UserController : Controller
{
    private readonly IUserService _userService;

    public UserController(IUserService userService) => _userService = userService;

    public IActionResult Index()
    {
        var users = _userService.GetAll();
        return View(users);
    }
}

// Service (Business Layer)
public class UserService : IUserService
{
    private readonly IUserRepository _repo;

    public UserService(IUserRepository repo) => _repo = repo;

    public IEnumerable<User> GetAll() => _repo.GetAllUsers();
}

// Repository (Data Access Layer)
public class UserRepository : IUserRepository
{
    private readonly AppDbContext _context;

    public UserRepository(AppDbContext context) => _context = context;

    public IEnumerable<User> GetAllUsers() => _context.Users.ToList();
}
```

- Benefits

  - Clear separation of concerns
  - Easy unit testing (mock each layer)
  - Scales better than MVC
  - Services and data layers can be reused (e.g., API and web share them)

- Questions

| Question                                       | Tip                                                          |
| ---------------------------------------------- | ------------------------------------------------------------ |
| What’s the difference between N-Layer and MVC? | MVC is UI-focused, N-Layer enforces business/data separation |
| What’s the purpose of the Service Layer?       | Central place for business logic                             |
| How do you test the service layer?             | Use mocks for repository and test logic in isolation         |

- Common Pitfalls

| Mistake                                 | Fix                                 |
| --------------------------------------- | ----------------------------------- |
| Logic in controller or repository       | Should be in service                |
| Entity Framework directly in controller | Should only be in the DAL           |
| Too much duplication between layers     | Use DTOs or mappers like AutoMapper |
| Not using interfaces                    | Breaks testability and abstraction  |

- When to use N-Layer?

  - Mid-sized projects
  - You want to follow best practices, but don’t need full domain-driven design
  - Business logic is not extremely complex

- If your app starts having:

  - Complex business rules
  - You want full separation between domain and infrastructure
  - You want to apply DDD

Then it's time for Onion Architecture.
