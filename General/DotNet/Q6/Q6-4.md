# Q6-4: What is the Hexagonal Architecture?

- Hexagonal Architecture (also called Ports and Adapters) is like Onion.
- But focuses more on decoupling the application from its delivery and infrastructure by using ports and adapters.
- Instead of layers, it models your app as a core with plug-in adapters.

- It answers the question: “How can I make my app testable and decoupled from frameworks like EF or ASP.NET?”

- Core Concepts

| Concept            | Meaning                                                                                      |
| ------------------ | -------------------------------------------------------------------------------------------- |
| Core / Application | The main logic. It depends on interfaces (ports), not frameworks                             |
| Ports              | Interfaces the core exposes (or uses) to communicate                                         |
| Adapters           | Concrete implementations (e.g., Web API, EF Core, SMTP, Files, etc.) that "plug in" to ports |

- Example:

- Core (Application + Ports)

```csharp
// Domain Entity
public class User
{
    public int Id { get; set; }
    public bool IsActive { get; private set; }

    public void Activate() => IsActive = true;
}

// Inbound Port (Use Case Interface)
public interface IUserActivationUseCase
{
    void ActivateUser(int id);
}

// Outbound Port (Repository)
public interface IUserRepository
{
    User GetById(int id);
    void Save(User user);
}

// Application Logic (Core)
public class UserActivationService : IUserActivationUseCase
{
    private readonly IUserRepository _repo;

    public UserActivationService(IUserRepository repo) => _repo = repo;

    public void ActivateUser(int id)
    {
        var user = _repo.GetById(id);
        user.Activate();
        _repo.Save(user);
    }
}
```

- Adapters

```csharp
//Inbound Adapter (Web API)
[ApiController]
[Route("api/users")]
public class UserController : ControllerBase
{
    private readonly IUserActivationUseCase _useCase;
    public UserController(IUserActivationUseCase useCase) => _useCase = useCase;

    [HttpPost("{id}/activate")]
    public IActionResult Activate(int id)
    {
        _useCase.ActivateUser(id);
        return Ok();
    }
}

//Outbound Adapter (EF Repository):
public class EfUserRepository : IUserRepository
{
    private readonly AppDbContext _context;

    public EfUserRepository(AppDbContext context) => _context = context;

    public User GetById(int id) => _context.Users.Find(id);
    public void Save(User user) => _context.SaveChanges();
}
```

- Questions:

| Question                               | Answer / Tip                                                                        |
| -------------------------------------- | ----------------------------------------------------------------------------------- |
| Why Hexagonal over Onion?              | Hexagonal gives more flexibility: Web, CLI, gRPC, and EF are all plugins (adapters) |
| What are Ports and Adapters?           | Ports = interfaces. Adapters = implementations.                                     |
| How is Hexagonal different from Onion? | Onion uses strict layers; Hexagonal uses boundaries + interfaces                    |
| Can you unit test the core?            | Yes! It has no framework dependencies. Just mock ports.                             |

- Common Pitfalls

| Mistake                                 | Fix                                                                     |
| --------------------------------------- | ----------------------------------------------------------------------- |
| Mixing EF or Controllers in core        | Core must have no dependencies on frameworks                            |
| Not naming interfaces clearly           | Name ports meaningfully (`IUserActivationUseCase`, `INotificationPort`) |
| Adapters talking directly to each other | All interaction must go through the core                                |

- When to Use Hexagonal?

  - Apps with multiple input/output types (e.g., web, CLI, queue, gRPC)
  - You want testable, clean, framework-independent core
  - You build long-living, flexible business systems
