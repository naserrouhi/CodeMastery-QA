# Q6-8: What is the difference between CQS and CQRS?

| Concept          | CQS                                                                   | CQRS                                                                         |
| ---------------- | --------------------------------------------------------------------- |----------------------------------------------------------------------------- |
| Core idea        | A method should either change state or return data — not both         | Separate models for reads and writes — different paths, different structures |
| Scope            | Method-level principle                                                | Application/system-level architectural pattern                               |
| Return rule      | Command → no return value (void) Query → return data, no side effects | Same, but enforced with different models and often handlers                  |
| Typical use      | Inside your domain or application service methods                     | Across the whole app (with MediatR, handlers, etc.)                          |
| Read/write model | Same object/class is often used                                       | Separate read/write models or data sources                                   |
| Goal             | Clear, predictable functions                                          | Scalability, performance, complexity handling                                |
| Complexity       | Simple                                                                | More complex (especially with events or messaging)                           |

- CQS Example:

```csharp
// Bad
public string ActivateUser(int userId)
{
    var user = _db.Users.Find(userId);
    user.IsActive = true;
    _db.SaveChanges();

    return "User Activated";
}

// Good
public void ActivateUser(int userId)
{
    var user = _db.Users.Find(userId);
    user.IsActive = true;
    _db.SaveChanges();
}

public User GetUserById(int id)
{
    return _db.Users.Find(id);
}
```

- CQRS Example

```csharp
public class ActivateUserCommand
{
    public int Id { get; set; }
}

public class ActivateUserHandler
{
    public void Handle(ActivateUserCommand cmd) { ... }
}

public class GetUserQuery
{
    public int Id { get; set; }
}

public class GetUserHandler
{
    public UserDto Handle(GetUserQuery query) { ... }
}
```

| What is CQS?      | A design principle: functions should either perform actions (commands) or return data (queries), not both. |
| What is CQRS?     | A higher-level architectural pattern that separates the read and write models entirely.                    |
| Are they related? | Yes — CQRS applies CQS, but takes it much further — to the system or architecture level.                   |
