# Q6-6: What is the Clean Architecture?

- It is a flexible, testable, and maintainable architecture that combines:
  - Onion architecture (concentric layers)
  - Hexagonal architecture (ports and adapters)
  - Domain-driven principles

> **Core rule**:
> **Dependencies must always point inward.**
> UI, DB, frameworks — all are external.
> **Business logic is the center.**

---

## 🧅 Clean Architecture Layers (Inside → Out):

```
[Entities Layer]         ← Core domain models (Enterprise-wide)
[Use Cases Layer]        ← Application-specific logic (business rules)
[Interface Adapters]     ← Controllers, Repositories, Presenters (convert in/out data)
[Frameworks & Drivers]   ← EF Core, Web API, SMTP, File system, etc.
```

---

## 📦 Typical Folder Structure:

```
MyApp/
├── Domain/               ← Entities, Enums, ValueObjects
├── Application/          ← Interfaces, DTOs, Use Cases
├── Infrastructure/       ← EF Core, External APIs (implements interfaces)
├── WebUI/                ← ASP.NET Core API (Controllers)
```

---

## 🧠 Simple Example Flow: "Activate User"

### 1️⃣ Domain Layer

```csharp
public class User
{
    public int Id { get; set; }
    public bool IsActive { get; private set; }

    public void Activate() => IsActive = true;
}
```

---

### 2️⃣ Application Layer

#### Interface:

```csharp
public interface IUserRepository
{
    User GetById(int id);
    void Save(User user);
}
```

#### Use Case:

```csharp
public class ActivateUserUseCase
{
    private readonly IUserRepository _repo;
    public ActivateUserUseCase(IUserRepository repo) => _repo = repo;

    public void Execute(int id)
    {
        var user = _repo.GetById(id);
        user.Activate();
        _repo.Save(user);
    }
}
```

---

### 3️⃣ Infrastructure Layer

```csharp
public class EfUserRepository : IUserRepository
{
    private readonly AppDbContext _context;
    public EfUserRepository(AppDbContext context) => _context = context;

    public User GetById(int id) => _context.Users.Find(id);
    public void Save(User user) => _context.SaveChanges();
}
```

---

### 4️⃣ Web Layer

```csharp
[ApiController]
[Route("api/users")]
public class UserController : ControllerBase
{
    private readonly ActivateUserUseCase _useCase;
    public UserController(ActivateUserUseCase useCase) => _useCase = useCase;

    [HttpPost("{id}/activate")]
    public IActionResult Activate(int id)
    {
        _useCase.Execute(id);
        return Ok();
    }
}
```

## ✅ Benefits

| Benefit               | Why it matters                                     |
| --------------------- | -------------------------------------------------- |
| Testable              | Core has no dependencies                           |
| Framework Independent | EF/Web/API are outer layers                        |
| Scalable              | Easy to add adapters (e.g., gRPC, background jobs) |
| DDD-friendly          | Promotes rich domain model                         |

## ✅ Interview Questions You May Be Asked

| Question                                        | Sample Answer / Tip                                                       |
| ----------------------------------------------- | ------------------------------------------------------------------------- |
| What is Clean Architecture?                     | A layered architecture where dependencies always point inward             |
| How does it differ from Onion or N-Layer?       | Stronger rules, more modular, formal use cases and separation             |
| Can you test business logic without a database? | Yes. Core is completely decoupled                                         |
| What belongs in each layer?                     | Entities in Domain, business logic in Application, EF/Web in outer layers |
| What is the role of Use Cases?                  | They coordinate application logic and enforce business rules              |

---

## 💣 Common Pitfalls

| Pitfall                                       | Fix                                                |
| --------------------------------------------- | -------------------------------------------------- |
| Putting EF in the Application layer           | Keep EF in Infrastructure                          |
| Making controllers call repositories directly | Use Cases should handle all logic                  |
| Not using DTOs to isolate layers              | Map entities to DTOs for input/output              |
| Forgetting Dependency Inversion               | Use interfaces to inject services and repositories |

---

## ✅ When to Use Clean Architecture

* Large applications
* Long-term projects that will evolve
* You want **maximum separation**, **testability**, and **scalability**
* You're working with **teams** or **microservices**
