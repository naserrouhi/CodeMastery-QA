## Q2: What are reference types?

- Reference types store a reference (memory address) to the actual data.

- Stored on the **heap** (dynamic memory, managed by the garbage collector).

- **Examples**:
  - Classes: `string`, `object`
  - Arrays: `int[]`
  - Delegates: `Action`, `Func`

- When you assign a reference type variable to another, both variables point to the **same memory location**. Changes to one variable affect the other.

  - Example:
    ```csharp
    int[] arr1 = new int[] { 1, 2, 3 };
    int[] arr2 = arr1; // arr2 points to the same array as arr1
    arr2[0] = 10;      // arr1[0] is also 10
    ```

---

### **Key Differences in C#**
| Feature                | Value Types                          | Reference Types                     |
|------------------------|--------------------------------------|-------------------------------------|
| **Storage**            | Stack                                | Heap                                |
| **Copy Behavior**      | Copy of the value is created         | Copy of the reference is created    |
| **Memory Management**  | Automatically freed (stack)          | Managed by garbage collector (heap) |
| **Performance**        | Faster for small data                | Slower due to indirection           |
| **Examples**           | `int`, `float`, `struct`, `enum`     | `class`, `string`, `array`          |

---

### **Special Cases in C#**
1. **Strings**:
   - In C#, `string` is a reference type but behaves like a value type because it is **immutable** (cannot be changed after creation).
   - Example:
     ```csharp
     string s1 = "Hello";
     string s2 = s1; // s2 points to the same "Hello" as s1
     s2 = "World";   // s1 remains "Hello", s2 now points to "World"
     ```

2. **Boxing and Unboxing**:
   - **Boxing**: Converting a value type to a reference type (e.g., `int` to `object`).
   - **Unboxing**: Converting a reference type back to a value type.
   - Example:
     ```csharp
     int i = 10;          // value type
     object o = i;        // boxing (value type to reference type)
     int j = (int)o;      // unboxing (reference type to value type)
     ```
   - **Performance Cost**: Boxing and unboxing involve memory allocation and copying, so they should be avoided in performance-critical code.

3. **Nullable Value Types**:
   - In C#, value types can be made nullable using the `?` operator (e.g., `int?`).
   - Example:
     ```csharp
     int? nullableInt = null; // value type that can hold null
     ```

---

### **When to Use Which?**
- Use **value types** for:
  - Small, simple data (e.g., numbers, booleans).
  - Data that doesn’t need to be shared or modified across multiple variables.
  - Performance-critical scenarios (e.g., in loops or calculations).

- Use **reference types** for:
  - Complex data structures (e.g., objects, arrays).
  - Data that needs to be shared or modified across multiple variables.
  - Scenarios where dynamic memory allocation is required.

---

### **Example Code**
```csharp
// Value Type Example
int x = 10;
int y = x; // y gets a copy of x's value
y = 20;    // x remains 10, y is now 20

// Reference Type Example
int[] array1 = new int[] { 1, 2, 3 };
int[] array2 = array1; // array2 points to the same array as array1
array2[0] = 10;        // array1[0] is also 10

// String Example (Reference Type with Value-Type Behavior)
string s1 = "Hello";
string s2 = s1; // s2 points to the same "Hello" as s1
s2 = "World";   // s1 remains "Hello", s2 now points to "World"
```
