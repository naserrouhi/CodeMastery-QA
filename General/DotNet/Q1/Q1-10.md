## Q1-10: What is the difference between stack trace and call stack?

- A stack trace is a list of method calls that were active at the time an error happened. It helps you find where and how a problem occurred in your code.


- The call stack is a part of memory that keeps track of method calls in a program. It follows the Last In, First Out (LIFO) rule, meaning the last called method is the first one to finish. When a method finishes, its data is removed.

- When a method is called, the stack stores a stack frame. It contains:

    1. Method Parameters → The values passed to the method.

    2. Local Variables → Variables declared inside the method.

    3. Return Address → The location in memory where the program should return after the method finishes.

        - The return address is not another stack frame.

        - The CPU uses this address to continue th execution.

    4. Saved Registers → Temporary values that need to be restored when returning to the caller method.

        - When a method is running, some of its variables and references (frequently-use small variables) are in CPU registers (For better calculation perfomance).


        - When calling another method, the CPU needs those registers for the new method, so it saves (backs up) the current register values into the stack.


        - After the method finishes, the CPU restores the saved registers from the stack and continues execution. (They still remain in CPU)
