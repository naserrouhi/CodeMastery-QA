# Q1-14: What's the difference between const and readonly?

1. readonly

    - A readonly field can only be assigned a value during its declaration or in a constructor.
    - The value is immutable after the constructor has run.
    - It can be instance or static.

```csharp
public class MyClass
{
    public readonly int readonlyField = 2;

    public MyClass(int readonlyField)
    {
        this.readonlyField = readonlyField;
    }
}

public class Program
{
    public static void Main()
    {
        var myClass = new MyClass(1);
        Console.WriteLine(myClass.readonlyField); //1
    }
}
```

2. const

    - It is a constant value that is known at compile-time and cannot change after its declaration.
    - Always static
    - Its value must be provided at the time of declaration.

```csharp
public class Program
{
    public static void Main()
    {
        Console.WriteLine(MyClass.ConstField);
    }
}

public class MyClass
{
    public const int ConstField = 2;
}
```

```csharp
public static const int ConstField = 2; //Error
```

3. static

    - It can be accessed without creating an instance of the class.
    - Can be applied to fields, properties, methods, and classes.

```csharp
public class Program
{
    public static void Main()
    {
        MyClass.IncrementCounter();

        Console.WriteLine(MyClass.StaticField); //1

        var myClass = new MyClass();
        var x = myClass.StaticField; //Error
        myClass.IncrementCounter(); //Error
    }
}

public class MyClass
{
    public static int StaticField = 0;

    public static void IncrementCounter()
    {
        StaticField++;
    }
}
```

4. Local Variables

    - They are declared inside methods or constructors and are limited in scope to that method.
    - Cannot have access modifiers like public or private.
    - They must be initialized before use.

```csharp
public class MyClass
{
    public void MyMethod()
    {
        var localVar = 10;
    }
}
```

5. Properties

    - It provides a get and set mechanism to access private fields.
    - Used for encapsulating data.

    - Why Use Properties in Simple Classes like DTOs?

        - You start with a simple DTO with public fields but later need to add logic.
        - it's a common convention to use properties instead of fields for public access to class data.
        - Some libraries (like Text.Json) use properties for serializing and deserializing objects.

6. Fields

    - They variables inside a class or struct, but outside any method, property, or constructor.
    - They can be instance or static.
    - Properties are generally preferred for public access to data, while fields are used for internal storage.
