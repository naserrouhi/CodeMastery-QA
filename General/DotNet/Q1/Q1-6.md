## Q1-6: Why strings are reference type?

Strings are Immutable means that once a string is created, its value cannot be changed.

When you change the value of a string variable, .NET creates a new string and stores it in the heap. The reference remains but th value changes and the old value makes garbage.

Normally, reference types work by sharing the same object in memory. But because strings are immutable, you can safely copy and treat strings like value types. Here's why:

When you assign a string to a new variable, it seems like you’re copying it (like a value type), but what actually happens is that the reference (address) to the string is copied.

Even if two variables reference the same string, it doesn’t matter, because you can’t change the string itself.


Example:

string a = "Hello";
string b = a;  // 'b' gets the same reference as 'a'

a = "World";    // 'a' points to "World", but 'b' still points to "Hello"

Before changing a to "World", both a and b point to the same string "Hello".

After the change, a now points to "World", but b still points to "Hello".

No change happened to the original string "Hello" because strings are immutable.
