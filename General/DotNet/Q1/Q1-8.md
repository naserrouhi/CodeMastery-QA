## Q1-8: What's the difference between class, truct, record an struct record?

All of them used to define types.


- **Class**

    - Reference Type

    - It can inherits from another class or some interfaces.

    - We use classes when the object is large and copying every time in stack would be expensive.


- **Struct**

    - Value type

```csharp
struct Person
{
    public string Name { get; set; }
}

var p1 = new Person { Name = "Alice" };
var p2 = p1;
p2.Name = "Bob";

Console.WriteLine(p1.Name); //Alice
```

    - It only can inherits from some interfaces.

    - It Has built-in value equality (compares content, not reference).

    - When you pass a struct as a parameter of a method, its entire value is copied. (Sometims compiler handles it in heap.) So we should use them fo small objects. In this situation, performance is better because it uses stcak.


- **Record**

    - Immutable.

```csharp
record Person(string Name, int Age);

var p1 = new Person("Alice", 25);
p1.Age = 30; ❌ ERROR

var p2 = p1 with { Age = 30 }; //✅
```

    - Reference Type

```csharp
record Person(string Name, int Age);
var p1 = new Person("Alice", 25);

p1 = p1 with { Age = 20 }; //Same reference, new vale

var p2 = p1 with { Age = 30 }; //new reference and value
```

    - We use them for dtos, immutable data models, value objects.

    - It Has built-in value equality.

    - It only can inherits from some interfaces.


---

- **Struct Record**

    - Immutable

    - Value Type

```csharp
record struct Person(string Name);

var p1 = new Person("Alice");
var p2 = p1;
p2.Name = "Bob";

Console.WriteLine(p1.Name); //Alice
```

    - It Has built-in value equality.

    - It only can inherits from some interfaces.

    - We use them for lightweight immutable objects to improve performance.
