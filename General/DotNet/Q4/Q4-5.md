# Q4-5: What is the Factory pattern?

- It is used to encapsulate object creation logic — especially when:

  - The process is dynamic or depends on some input (like type, config, role).
  - You don't want to use new directly in your code.

- Real-world analogy

  - A car dealership gives you a car based on your needs.
  - You say “I want a sedan,” and the dealer gives you one.
  - You don’t care how they got it — just that it’s a car.

- Example:

```csharp
public interface IVehicle
{
    void Drive();
}

public class Car : IVehicle
{
    public void Drive() => Console.WriteLine("Driving a car");
}

public class Bike : IVehicle
{
    public void Drive() => Console.WriteLine("Riding a bike");
}

public static class VehicleFactory
{
    public static IVehicle Create(string type)
    {
        return type.ToLower() switch
        {
            "car" => new Car(),
            "bike" => new Bike(),
            _ => throw new ArgumentException("Unknown vehicle type")
        };
    }
}

var vehicle = VehicleFactory.Create("car");
vehicle.Drive();
```

- Common Use Cases:

  1. Switching between services dynamically

```csharp
IPaymentService service = PaymentFactory.Create("stripe");
```

  2. Creating services in background jobs, middleware, or hosted services
     - In IHostedService, you may not be in a request scope, so you use a factory to resolve services dynamically using IServiceProvider.

```csharp
var processor = serviceProvider.GetRequiredService<IProcessorFactory>().Create("daily");
```

  3. Encapsulating 3rd-party library complexity

```csharp
var client = HttpClientFactory.Create("weatherApi");
```

  4. Deserializing polymorphic data

```csharp
var handler = MessageHandlerFactory.Create(message.Type);
```
