# Q4-6: What is the Builder pattern?

- It is used when:

  - Creating an object involves multiple steps or configurations.
  - You want to make object construction more readable, controlled, and fluent.
  - It’s perfect for building complex objects, like a big Invoice, House, or EmailMessage.

- Real-world analogy:

  - Building a burger at a fast-food chain.
  - You add cheese, pickles, sauce, etc. step by step — and in the end you get your final burger.

- Example:

```csharp
public class Burger
{
    public bool HasCheese { get; private set; }
    public bool HasLettuce { get; private set; }
    public bool HasTomato { get; private set; }

    private Burger() {}

    public class Builder
    {
        private readonly Burger _burger = new();

        public Builder AddCheese()
        {
            _burger.HasCheese = true;
            return this;
        }

        public Builder AddLettuce()
        {
            _burger.HasLettuce = true;
            return this;
        }

        public Builder AddTomato()
        {
            _burger.HasTomato = true;
            return this;
        }

        public Burger Build()
        {
            return _burger;
        }
    }
}

var burger = new Burger.Builder()
    .AddCheese()
    .AddTomato()
    .Build();
```

- Common Use Cases:

1. Building complex domain models or DTOs
   - Used when:
     - The object has many optional or conditional parts.
     - The constructor would take too many arguments.

```csharp
var report = new ReportBuilder()
    .AddTitle("Sales")
    .AddChart()
    .AddSummary()
    .Build();
```

2. Creating test data for unit tests

```csharp
var user = new UserBuilder()
    .WithName("Admin")
    .WithRoles("SuperAdmin")
    .Build();
```

3. Fluent configuration in libraries

```csharp
app.UseRouting()
   .UseAuthentication()
   .UseAuthorization()
   .UseEndpoints(...);
```

4. Building SQL queries or expressions

```csharp
var query = new SqlQueryBuilder()
    .Select("Name", "Age")
    .From("Users")
    .Where("Age > 18")
    .Build();
```

- What’s the difference between Factory and Builder?

  - Factory:
    - Returns a complete object in one step.
    - Great when object selection depends on a condition.
    - Hides new keyword and creation logic.
    - Use Factory when what you create varies.

  - Builder:
    - Builds an object step-by-step.
    - Good for complex or optional configurations.
    - Supports fluent chaining and better readability.
    - Use Builder when how you create something varies or is complex.
