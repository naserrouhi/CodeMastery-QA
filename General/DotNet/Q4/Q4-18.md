# Q4-18: What Is the Specification pattern?

- It is a powerful design pattern often used in DDD to encapsulate business rules and query logic in a reusable, testable, and composable way.

- It allows you to define business rules or query filters as objects, and then:
    - Reuse them
    - Combine them (AND, OR, NOT)
    - Apply them to in-memory objects or database queries

- Where It’s Used

    - In DDD for encapsulating domain rules
    - In repository querying to keep data access logic clean
    - In unit testing (can test rules without DB)
    - In complex filtering/searching scenarios

- Example

```csharp
public interface ISpecification<T>
{
    Expression<Func<T, bool>> ToExpression();
    bool IsSatisfiedBy(T entity);
}

public abstract class Specification<T> : ISpecification<T>
{
    public abstract Expression<Func<T, bool>> ToExpression();

    public bool IsSatisfiedBy(T entity)
    {
        var predicate = ToExpression().Compile();
        return predicate(entity);
    }

    public Specification<T> And(Specification<T> other) => new AndSpecification<T>(this, other);
    public Specification<T> Or(Specification<T> other) => new OrSpecification<T>(this, other);
}

public class VIPCustomerSpec : Specification<Customer>
{
    public override Expression<Func<Customer, bool>> ToExpression() => customer => customer.IsVIP;
}

public class MinOrderTotalSpec : Specification<Order>
{
    private readonly decimal _minAmount;

    public MinOrderTotalSpec(decimal minAmount) => _minAmount = minAmount;

    public override Expression<Func<Order, bool>> ToExpression() => order => order.Total >= _minAmount;
}
```

```csharp
var spec = new VIPCustomerSpec().And(new MinOrderTotalSpec(500));

var results = _db.Orders.Where(spec.ToExpression()).ToList();
```

```csharp
var bigOrders = new MinOrderTotalSpec(1000);
var vipCustomers = new VIPCustomerSpec();
var querySpec = bigOrders.And(vipCustomers);
```

```csharp
var spec = new VIPCustomerSpec();
Assert.True(spec.IsSatisfiedBy(new Customer { IsVIP = true }));
```

- Benefits

| Benefit                | Why it matters                               |
| ---------------------- | -------------------------------------------- |
| Encapsulation          | Keeps rules in one place                     |
| Reusability            | Define once, use in queries, tests, services |
| Testability            | Easily unit test specifications              |
| Composability          | Combine filters dynamically                  |
| Separation of concerns | Keeps your domain model and repository clean |

- Pitfalls

| Mistake                                  | Fix                                    |
| ---------------------------------------- | -------------------------------------- |
| Putting all logic in controllers         | Use specs for filtering logic          |
| Making specs too generic                 | Keep them tied to business concepts    |
| Using specifications for trivial queries | Use only where complexity justifies it |

- Questions:

| Question                           | Answer                                                                             |
| ---------------------------------- | -------------------------------------------------------------------------------------- |
| What is the Specification Pattern? | A pattern to encapsulate and reuse business rules and filtering logic                  |
| How do you implement it in .NET?   | Using `Expression<Func<T, bool>>` and composing with LINQ                              |
| Where is it used?                  | In repositories, domain rules, and unit tests                                          |
| What are the benefits?             | Reusability, testability, clean code separation                                        |
| How is it different from strategy? | Strategy executes behavior; specification evaluates whether something satisfies a rule |
