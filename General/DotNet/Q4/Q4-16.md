# Q4-16: In Entity Framework, which collection type should I use for one-to-many navigation properties: ICollection<T>, List<T>, or IEnumerable<T>?

- ICollection<T> is the best practice (cleaner, more abstract, future-proof)

- ICollection<T>

    - EF Core needs needs read/write access, not just read-only.
    - It provides: .Add(), .Remove(), and supports iteration (foreach)
    - This makes it ideal for EF’s internal tracking and change detection

- List<T>
    
    - You can use it, and EF will work fine.
    - But it ties your entity to a specific implementation.
    - ICollection<T> is more flexible and allows easier testing or mocking.

- IEnumerable<T>

    - Don’t use IEnumerable<T> for navigation properties.
    - It’s read-only — no .Add() or .Remove()
    - EF can’t update it or track changes properly.
    - Can lead to runtime issues.
