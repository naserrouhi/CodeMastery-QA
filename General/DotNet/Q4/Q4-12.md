# Q4-12: What is the Outbox pattern?

- It solves the problem of keeping your database and message broker in sync.
- Instead of sending events directly to the message queue right after saving to DB,
- You store the event in a database table (called Outbox) inside the same transaction.
- Then a background process reads from the outbox and sends the events reliably.
- The Outbox Pattern solves the problem of reliably sending messages in distributed systems.
- It ensures changes to the database and outgoing messages happen in the same transaction by storing messages in an Outbox table, which a background worker later processes.

- It ensures that:

  - You save your changes (e.g., to a database),
  - And publish related events (e.g., to Kafka, RabbitMQ, etc.)
  - without risking losing data or sending duplicates

- Example:

```csharp
public class User
{
    public int Id { get; set; }
    public string Email { get; set; }
}

public class OutboxMessage
{
    public Guid Id { get; set; } = Guid.NewGuid();
    public string Type { get; set; } // e.g. "UserCreated"
    public string Payload { get; set; }
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    public bool Processed { get; set; } = false;
}

public void RegisterUser(User user)
{
    var userCreatedEvent = new
    {
        Id = user.Id,
        Email = user.Email
    };

    _dbContext.Users.Add(user);

    var message = new OutboxMessage
    {
        Type = "UserCreated",
        Payload = JsonSerializer.Serialize(userCreatedEvent)
    };

    _dbContext.OutboxMessages.Add(message);

    _dbContext.SaveChanges();
}

public class OutboxDispatcher : BackgroundService
{
    private readonly IServiceProvider _provider;

    public OutboxDispatcher(IServiceProvider provider)
    {
        _provider = provider;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            using var scope = _provider.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();

            var messages = db.OutboxMessages
                .Where(m => !m.Processed)
                .Take(10)
                .ToList();

            foreach (var msg in messages)
            {
                try
                {
                    // send to message broker (e.g., RabbitMQ, Kafka)
                    Console.WriteLine($"Sending: {msg.Type} → {msg.Payload}");

                    msg.Processed = true;
                }
                catch (Exception)
                {
                    // retry later
                }
            }

            await db.SaveChangesAsync();
            await Task.Delay(5000, stoppingToken);
        }
    }
}
```

- Common Use Cases:

  - Microservices that publish domain events (e.g., UserRegistered, OrderPlaced)
  - Event sourcing systems that must not lose events
  - Reliable messaging without needing distributed transactions
  - Decoupling side effects (e.g., sending emails, updating search indexes)
