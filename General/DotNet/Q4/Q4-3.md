# Q4-3: What is the Repository pattern?

- It is like a middle layer between your business logic and your data access code.
- Hides the details of data access (EF Core, SQL, MongoDB, etc.)
- Exposes a clean, consistent API to your domain or service layer.
- Makes your app easier to test, swap databases, or change how data is stored.
- Example: We use repositories to abstract away persistence concerns so my business logic doesn’t depend on EF Core or SQL.

- Real-World Analogy:

  - Imagine your app wants to work with customers.
  - Instead of writing SQL queries or EF Core logic everywhere, you create a CustomerRepository that handles all data access.

- Example:

```csharp
public class Customer
{
    public int Id { get; set; }
    public string Name { get; set; }
}

public interface ICustomerRepository
{
    Customer GetById(int id);
    IEnumerable<Customer> GetAll();
    void Add(Customer customer);
    void Save();
}

public class CustomerRepository : ICustomerRepository
{
    private readonly AppDbContext _context;

    public CustomerRepository(AppDbContext context)
    {
        _context = context;
    }

    public Customer GetById(int id)
    {
        return _context.Customers.Find(id);
    }

    public IEnumerable<Customer> GetAll()
    {
        return _context.Customers.ToList();
    }

    public void Add(Customer customer)
    {
        _context.Customers.Add(customer);
    }

    public void Save()
    {
        _context.SaveChanges();
    }
}

public class CustomerService
{
    private readonly ICustomerRepository _repository;

    public CustomerService(ICustomerRepository repository)
    {
        _repository = repository;
    }

    public void RegisterCustomer(string name)
    {
        var customer = new Customer { Name = name };
        _repository.Add(customer);
        _repository.Save();
    }
}
```

- Common Use Cases:

  - Wrapping Entity Framework, Dapper, or MongoDB logic.
  - Making unit testing easier by mocking repositories.
  - Centralizing business-friendly data access (e.g., GetActiveCustomers()).
  - Keeping your service layer clean and database-agnostic.
