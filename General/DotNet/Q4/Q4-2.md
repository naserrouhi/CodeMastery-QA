# Q4-2: What is Singleton pattern?

- It ensures that a class has only one instance during the lifetime of the application.
- You provide a global point of access to that single instance.
- It’s useful when having multiple instances would cause problems, or when you want to share state or resources (like configuration or cache).
- Don’t put logic or mutable state inside a singleton unless you know it’s safe.
- In ASP.NET Core, prefer using the built-in DI container to register services as AddSingleton instead of implementing your own singleton class.

- Real-World Analogy:

  - Think of a printer spooler. There should be only one instance managing print jobs. If each program had its own spooler, documents would print in the wrong order.

- Example:

```csharp
public class AppConfig
{
    private static AppConfig _instance;
    private static readonly object _lock = new();

    public string ConnectionString { get; private set; }

    private AppConfig()
    {
        // Simulate reading from a config file
        ConnectionString = "Server=.;Database=AppDb;Trusted_Connection=True;";
    }

    public static AppConfig Instance
    {
        get
        {
            if (_instance == null)
            {
                lock (_lock) // Thread-safe
                {
                    if (_instance == null)
                        _instance = new AppConfig();
                }
            }
            return _instance;
        }
    }
}
```

- Common Use Cases:

  - Configuration settings (e.g., AppConfig, EnvironmentService)
  - Caching layer
  - Logger service
  - Global state or shared resource management
