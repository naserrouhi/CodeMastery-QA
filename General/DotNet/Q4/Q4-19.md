# Q4-18: Explain types of indexes in SQL Server.

- Clustered Index

    - The actual data is stored in the index
    - Only one clustered index per table
    - The rows are physically ordered based on this index
    - Good for: Searching by primary key, range queries on sorted data
    - Bad for: Frequent inserts in middle of range (causes page splits)

```sql
CREATE CLUSTERED INDEX IX_Users_Id ON Users(Id);
```

- Non-Clustered Index

    - Stores a separate copy of the index
    - Points to the actual data row (via a row pointer or primary key)
    - You can have many non-clustered indexes on a table
    - Good for: Searching/filtering on frequently queried columns
    - Bad for: Large result sets or columns not included in index (causes lookups)

```sql
CREATE NONCLUSTERED INDEX IX_Users_Email ON Users(Email);
```

- Unique Index

    - Like any index, but enforces uniqueness
    - Often used for constraints like emails or usernames
    - Good for: Enforcing unique business rules

```sql
CREATE UNIQUE INDEX IX_Users_Email ON Users(Email);
```

- Composite Index

    - Index on multiple columns
    - Good for: Queries filtering by both columns in left-to-right order
    - Only works well if you filter by first column (CustomerId) — else index isn't used

```sql
CREATE INDEX IX_Orders_CustomerId_Status ON Orders(CustomerId, Status);
```

- Full-Text Index

    - Specialized index for text searching (e.g., contains, near, inflection)
    - Good for: Searching large text fields (e.g., blog posts, articles)
    - Requires setup and has its own query syntax (`CONTAINS`, `FREETEXT`)

```sql
CREATE FULLTEXT INDEX ON Articles(Title, Body)
    KEY INDEX PK_Articles;
```

- Filtered Index (SQL Server)

    - A partial index created with a `WHERE` clause
    - Good for: Indexing sparse data (e.g., only active users, only pending orders)
    - Smaller and faster than full-table index

```sql
CREATE NONCLUSTERED INDEX IX_Orders_Pending
ON Orders(Status)
WHERE Status = 'Pending';
```

- Covering Index

    - An index that contains all the columns your query needs (so SQL doesn't touch the table)
    - Good for: Fully satisfying SELECTs without lookup
    - Boosts performance a lot when tuned correctly

```sql
CREATE NONCLUSTERED INDEX IX_Orders_Covering
ON Orders(CustomerId, Status)
INCLUDE (TotalPrice, OrderDate);
```

- XML and Spatial Indexes

    - XML Index: Efficient querying of XML columns
    - Spatial Index: Fast geo-location queries (latitude/longitude, maps)
