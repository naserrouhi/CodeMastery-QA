# Q4-7: What is the Observer pattern?

- It allows one object (subject) to notify other objects (observers) automatically when its state changes.
- One-to-many relationship
- Observers “subscribe” to a subject
- When the subject changes, all observers get notified
- The Observer pattern lets you define a subscription mechanism to notify multiple objects about changes to the subject.
- It’s useful when multiple parts of an app need to stay in sync with some shared state, like UI, logs, or data feeds.

- Real-world analogy

  - Imagine a YouTube channel (subject).
  - When you subscribe to the channel (observer), you get a notification whenever a new video is uploaded.

- Example:

```csharp
public interface IWeatherObserver
{
    void Update(float temperature);
}

public class WeatherStation
{
    private readonly List<IWeatherObserver> _observers = new();
    private float _temperature;

    public void Subscribe(IWeatherObserver observer)
    {
        _observers.Add(observer);
    }

    public void Unsubscribe(IWeatherObserver observer)
    {
        _observers.Remove(observer);
    }

    public void SetTemperature(float temperature)
    {
        _temperature = temperature;
        NotifyObservers();
    }

    private void NotifyObservers()
    {
        foreach (var observer in _observers)
            observer.Update(_temperature);
    }
}

public class PhoneDisplay : IWeatherObserver
{
    public void Update(float temperature)
    {
        Console.WriteLine($"Phone Display: {temperature}°C");
    }
}

public class WebAppDisplay : IWeatherObserver
{
    public void Update(float temperature)
    {
        Console.WriteLine($"Web App: {temperature}°C");
    }
}

var station = new WeatherStation();

var phone = new PhoneDisplay();
var web = new WebAppDisplay();

station.Subscribe(phone);
station.Subscribe(web);

station.SetTemperature(25);
```

- Common Use Cases:

  - Event systems (e.g., UI events, game events, logging)
  - Real-time updates in dashboards or notifications
  - Model-View-Controller (MVC) — the view observes the model
  - Entity Framework change tracking under the hood uses similar concepts
  - Pub-Sub systems like messaging brokers or background jobs
  - Reactive programming (IObservable<T> in Rx.NET is built on this pattern)
