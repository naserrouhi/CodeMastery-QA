# Q4-20: What are the types of lock in database?

- Lock Granularity

| Level          | Description                                         |
| -------------- | --------------------------------------------------- |
| Row-level      | Locks a specific row (fine-grained, low contention) |
| Page-level     | Locks an 8KB page (multiple rows)                   |
| Table-level    | Locks entire table (rare, expensive)                |
| Database-level | Locks whole DB (during backups, etc.)               |

- Shared Lock (S)

    - Used when reading data
    - Multiple shared locks allowed at the same time
    - Prevents writes during read

```sql
SELECT * FROM Orders WITH (HOLDLOCK);
```

- Exclusive Lock (X)

    - Used during INSERT, UPDATE, DELETE
    - No other read or write can happen on locked resource
    - Ensures full isolation

```sql
UPDATE Orders SET Status = 'Done' WHERE Id = 1;
```

- Update Lock (U)

    - A hybrid lock to prevent deadlocks
    - Used before converting to Exclusive lock
    - Only one process can hold it — avoids race conditions in updates
    - E.g., during `SELECT ... FOR UPDATE`, the DB places a U lock first, then promotes it to X

- Intent Locks (IS, IX, SIX)

    - These locks don't block** each other directly but are used by SQL Server's lock manager to detect conflicts and escalation.

| Lock                               | Meaning                                               |
| ---------------------------------- | ----------------------------------------------------- |
| IS (Intent Shared)                 | "I intend to take a Shared lock at a lower level"     |
| IX (Intent Exclusive)              | "I intend to take an Exclusive lock at a lower level" |
| SIX (Shared with Intent Exclusive) | Table shared lock + intent to X-lock rows             |

- Schema Lock

    - `Schema Stability` (`Sch-S`) — allows reading while preventing structural changes
    - `Schema Modification` (`Sch-M`) — used when altering schema (blocks everything)

```sql
ALTER TABLE Orders ADD COLUMN Discount INT;  -- Sch-M lock
```

- Bulk Update Lock (BU)

    - Used during BULK INSERT operations
    - Reduces overhead by using minimal logging

| Mode  | Used For               | Blocks Reads? | Blocks Writes? |
| ----- | ---------------------- | ------------- | -------------- |
| S     | Read                   | ❌            | ✅             |
| X     | Write                  | ✅            | ✅             |
| U     | Pre-update             | ❌            | ✅             |
| IS    | Intent to read         | ❌            | ❌             |
| IX    | Intent to write        | ❌            | ❌             |
| SIX   | Read + intent to write | ❌            | ✅             |
| Sch-S | Schema read            | ❌            | ✅             |
| Sch-M | Schema change          | ✅            | ✅             |

- Locks vs Isolation Levels

| Isolation Level  | Lock Behavior                                 |
| ---------------- | --------------------------------------------- |
| Read Uncommitted | No locks — can read dirty data                |
| Read Committed   | Shared locks for reads                        |
| Repeatable Read  | Locks rows to prevent re-reading changed data |
| Serializable     | Locks rows + range to prevent phantom reads   |
| Snapshot         | Uses row versioning, no locks for reads       |

- Questions:

| Question                                        | Answer                                                                       |
| ----------------------------------------------- | -----------------------------------------------------------------------------|
| What's a shared lock?                           | Used for reads, allows other readers, blocks writers                         |
| Can multiple exclusive locks exist on same row? | No — exclusive locks are mutually blocking                                   |
| What is a deadlock?                             | Two sessions each hold a lock and wait for the other — both block forever    |
| How to avoid deadlocks?                         | Use consistent ordering, smaller transactions, proper isolation levels       |
| What's lock escalation?                         | SQL Server promotes row/page locks to table-level to reduce overhead         |
| What’s an Intent Lock?                          | A lightweight lock telling SQL Server a lock will be taken at a lower level  |
