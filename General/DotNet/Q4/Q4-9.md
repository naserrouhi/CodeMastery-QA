# Q4-9: What is the Strategy pattern?

- It allows you to define a family of algorithms, put each one in a separate class, and make them interchangeable at runtime.
- You extract the varying part of a behavior into separate classes.
- You can switch behavior dynamically.
- It follows Open/Closed Principle.
- The Strategy pattern lets you define interchangeable behaviors and use them without changing the code that uses them.
- It’s great when you want to swap logic at runtime or keep business rules isolated and pluggable.

- Real-world analogy:
  
  - Imagine a navigation app.
  - You can choose to get directions by car, bike, or walking.
  - Each strategy gives a different route, but the app uses them through the same interface.

- Example:

```csharp
public interface IPaymentStrategy
{
    void Pay(decimal amount);
}

public class CreditCardPayment : IPaymentStrategy
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount:C} with Credit Card.");
    }
}

public class PayPalPayment : IPaymentStrategy
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount:C} with PayPal.");
    }
}

public class CryptoPayment : IPaymentStrategy
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount:C} with Bitcoin.");
    }
}

public class PaymentProcessor
{
    private IPaymentStrategy _strategy;

    public void SetStrategy(IPaymentStrategy strategy)
    {
        _strategy = strategy;
    }

    public void Process(decimal amount)
    {
        if (_strategy == null)
            throw new InvalidOperationException("Payment strategy not set.");

        _strategy.Pay(amount);
    }
}

var processor = new PaymentProcessor();

processor.SetStrategy(new CreditCardPayment());
processor.Process(100);

processor.SetStrategy(new PayPalPayment());
processor.Process(150);
```

- Common Use Cases:

  - Dynamic business rules
    - Example: Different pricing algorithms, discount rules, or tax calculations.

  - Sorting, filtering, or routing logic
    - You might switch strategies depending on user role, input, or config.

  - Behavior that varies but shares a contract
    - Such as logging to file vs database, or compression with zip vs gzip.

  - Replacing long if-else or switch blocks
    - Strategy is a clean alternative to messy conditional logic.

  - Unit testing
    - You can easily inject mock strategies for testing.
