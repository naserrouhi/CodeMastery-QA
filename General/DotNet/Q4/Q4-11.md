# Q4-11: What is the Proxy pattern?

- It is a structural pattern where a stand-in object (proxy) controls access to another object (the real one).
- The Proxy Pattern provides a substitute object that controls access to another object.
- It's useful for adding logging, access control, caching, or lazy loading without modifying the original object.

- It can:
  - Add extra logic before/after delegating to the real object
  - Protect the real object (security)
  - Delay creation of the real object (lazy loading)
  - Log, cache, or measure access

- Real-world analogy:
  
  - Think of a receptionist at an office.
  - You don’t go straight to the CEO. You talk to the receptionist (proxy), and they control access:
  - “Why are you here?” “Do you have an appointment?”

- Example:

```csharp
public interface IDocument
{
    void Display();
}

public class RealDocument : IDocument
{
    private readonly string _fileName;

    public RealDocument(string fileName)
    {
        _fileName = fileName;
    }

    public void Display()
    {
        Console.WriteLine($"Displaying document: {_fileName}");
    }
}

public class DocumentProxy : IDocument
{
    private RealDocument _realDocument;
    private readonly string _fileName;
    private readonly string _userRole;

    public DocumentProxy(string fileName, string userRole)
    {
        _fileName = fileName;
        _userRole = userRole;
    }

    public void Display()
    {
        if (_userRole != "Admin")
        {
            Console.WriteLine("Access denied: only Admins can view the document.");
            return;
        }

        _realDocument ??= new RealDocument(_fileName); // Lazy loading
        _realDocument.Display();
    }
}

var doc1 = new DocumentProxy("FinancialReport.pdf", "Guest");
doc1.Display();

var doc2 = new DocumentProxy("FinancialReport.pdf", "Admin");
doc2.Display();
```

- Common Use Cases:

  - Security proxies
    - Validate roles or permissions before allowing access (as in the example above).

  - Caching proxies
    - Cache expensive method results (e.g., API, DB) without modifying the original service.

  - Lazy-loading
    - Delay creating heavy objects (like images, data files) until needed.

  - Remote proxies (WCF, gRPC)
    - Talk to objects on other servers — the proxy handles communication.

  - Logging or performance monitoring
    - Wrap services and log calls transparently.
