# Q4-4: What is the UnitOfWork pattern?

- Groups multiple repository operations into a single transaction.
- Ensures that all changes are committed or rolled back together.
- Manages consistency and avoids partial updates.
- You can think of it as a coordinator of changes.

- Real-World Analogy:

  - Imagine you're buying items online.
  - You Add items to cart, Apply a discount, Finalize payment
  - All these steps must succeed together. If one fails (like payment), everything should be canceled.

- Why use Unit of Work with EF Core?

  - Explicit grouping of multiple repositories
    - Instead of injecting 3 different repositories into your service, inject one UnitOfWork that exposes all of them.

  - Transactional behavior across repositories
    - Ensures all changes from different repos are committed in one place.

  - Clear and consistent commit point
    - Only the UnitOfWork calls SaveChanges(), not individual repositories.

  - Testability
    - You can easily mock IUnitOfWork in your unit tests instead of mocking each repository.

  - Decoupling from EF Core
    - You can replace EF Core later (e.g., with Dapper) and your service layer doesn’t break.

- Example:

  - EF Core's DbContext does act like a unit of work — but adding a UoW pattern gives you structure, abstraction, and better testability.

```csharp
public interface ICustomerRepository
{
    void Add(Customer customer);
}

public interface IOrderRepository
{
    void Add(Order order);
}

public interface IUnitOfWork
{
    ICustomerRepository Customers { get; }
    IOrderRepository Orders { get; }
    void Save();
}

public class UnitOfWork : IUnitOfWork
{
    private readonly AppDbContext _context;

    public UnitOfWork(AppDbContext context)
    {
        _context = context;
        Customers = new CustomerRepository(context);
        Orders = new OrderRepository(context);
    }

    public ICustomerRepository Customers { get; }
    public IOrderRepository Orders { get; }

    public void Save()
    {
        _context.SaveChanges();
    }
}

public class CheckoutService
{
    private readonly IUnitOfWork _unitOfWork;

    public CheckoutService(IUnitOfWork unitOfWork)
    {
        _unitOfWork = unitOfWork;
    }

    public void Checkout(Customer customer, Order order)
    {
        _unitOfWork.Customers.Add(customer);
        _unitOfWork.Orders.Add(order);
        _unitOfWork.Save();
    }
}
```
