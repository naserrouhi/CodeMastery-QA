# Q8-5: Why REST APIs Should Be Stateless & Why That Simplifies Scaling?

- What Stateless Means in REST?

    - Each request from a client to the server must contain all the information needed to process it.
    - The server does not store client-specific state between requests.

- Why It Simplifies Scaling?

    - Imagine you have multiple servers (Server A, Server B, Server C) behind a load balancer.

    - If state is stored on the server (session data in RAM)
        - The load balancer must keep sending you to the same server (sticky sessions) → scaling is harder, failover is tricky.

    - If state is stored on the client (JWT tokens, etc.) or in a shared database/cache (Redis)
        - Any server can handle your request → you can freely add/remove servers.

- Statelessness simplifies scaling because:
    - Any request can be served by any instance.
    - Removing the need for server-side session storage.
    - Making horizontal scaling easier.
