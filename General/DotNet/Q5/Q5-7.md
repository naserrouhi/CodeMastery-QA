# Q5-7: What is HashSet?

- It is an unordered collection of unique elements — it does not allow duplicates, and it does not guarantee order.

- Internally it uses a hash table to store items.
    - Fast lookup and insertion (O(1) on average).
    - Ensures uniqueness.
    - Unordered.

- Example:

```csharp
var set = new HashSet<int>();

set.Add(1);
set.Add(2);
set.Add(3);
set.Add(2);  // ignored (duplicate)

foreach (var n in set)
    Console.WriteLine(n);
// Output: 1, 2, 3 (order is NOT guaranteed)
```

- You can also create a set from an array or list:

```csharp
var list = new List<int> { 1, 2, 2, 3 };
var setFromList = new HashSet<int>(list);
```

- When should you use HashSet<T>?

    - You need fast lookup: “Does this element exist?”
    - You need to enforce uniqueness of elements.
    - You don’t care about the order of elements.

- Advantages:

    - Ensures uniqueness automatically.
    - Very fast for Contains checks.
    - Supports set operations.

- Disadvantages

    - No order.
    - More memory than a simple list.
    - Not indexable.

- Tricks:

- You can try to add the same element twice — but the second Add simply returns false and does nothing.

```csharp
bool added = set.Add(2);  // returns false if already exists
```

- HashSet<T> supports useful mathematical set operations:

```csharp
var a = new HashSet<int> { 1, 2, 3 };
var b = new HashSet<int> { 3, 4, 5 };

a.IntersectWith(b);  // a now contains { 3 }
```

- Other operations:

```csharp
    UnionWith()
    ExceptWith()
    IsSubsetOf()
    IsSupersetOf()
```

- How is HashSet<T> different from List<T>?

    - HashSet<T> is unordered and enforces uniqueness, List<T> allows duplicates and keeps order.

- Use-case for HashSet<T>.

    - Checking if a value already exists quickly, removing duplicates, graph algorithms where visited nodes must be tracked.
