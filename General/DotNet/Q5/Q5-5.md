# Q5-5: What is Queue?

- It is a First-In-First-Out (FIFO) collection — the first item you add is the first item you get out.

- Think of it like a line of people waiting for service: the first person in line is served first.
    - Ordered.
    - Dynamic size.
    - Very fast enqueue and dequeue.

- Example:

```csharp
var queue = new Queue<string>();

queue.Enqueue("A");
queue.Enqueue("B");
queue.Enqueue("C");

Console.WriteLine(queue.Dequeue());  // Output: A
Console.WriteLine(queue.Peek());     // Output: B
```

- Enqueue(value) → add item to the back of the queue.
- Dequeue() → remove and return the item at the front.
- Peek() → just look at the item at the front without removing it.

- When should you use Queue<T>?

    - You need to process items in order of arrival.
    - You want efficient (O(1)) enqueue and dequeue operations.
    - You don’t need random access to elements in the middle.

- Advantages:

    - Perfect for FIFO scenarios.
    - Very fast and efficient.
    - Type-safe.

- Disadvantages

    - No random access.
    - Can only operate on front and back.

- Tricks:

- If you call Dequeue() on an empty queue, it throws InvalidOperationException.

```csharp
if (queue.Count > 0)
    queue.Dequeue();
```

- You cannot access queue[0] — it’s not indexable.
- Use Peek() to see the front.

- What’s the difference between Queue<T> and List<T>?
    
    - Queue<T> is optimized for FIFO operations, very efficient. List<T> can be used as a queue but is slower (RemoveAt(0) shifts all elements).

- Use-case for Queue<T>:

    - Task scheduling, breadth-first search (BFS), printer job queue.
