# Q5-9: What is SortedDictionary?

- It is just like Dictionary<TKey, TValue> — a collection of unique key-value pairs —
- but it keeps the keys in sorted order (according to the key’s comparer).

- Internally it uses a balanced binary search tree (Red-Black tree), not a hash table.
    - Unique keys.
    - Keys always sorted.
    - Slower than Dictionary for insert/lookup.

- Example:

```csharp
var sortedDict = new SortedDictionary<int, string>();

sortedDict.Add(3, "Three");
sortedDict.Add(1, "One");
sortedDict.Add(2, "Two");

foreach (var kvp in sortedDict)
    Console.WriteLine($"{kvp.Key}: {kvp.Value}");
// Output: 
// 1: One
// 2: Two
// 3: Three
```

- When should you use SortedDictionary<TKey, TValue>?

    - You need a map of keys to values, and you care about the keys being sorted.
    - You still want fast lookups by key (O(log n)).

- Advantages:

    - Keys are always sorted.
    - Lookup and insert are still reasonably fast.
    - You can define custom sort order.

- Disadvantages:

    - Slower than Dictionary.
    - Uses more memory.
    - No indexing by position.

- Tricks:

- Lookups and inserts are O(log n) because of the tree, while Dictionary is O(1) on average.
- So if you don’t care about order, use Dictionary — it’s faster.

- You can pass a custom comparer to sort keys differently (like case-insensitive strings).

```csharp
var caseInsensitiveDict = new SortedDictionary<string, int>(StringComparer.OrdinalIgnoreCase);
```

- How is SortedDictionary different from Dictionary?
    
    - SortedDictionary keeps keys sorted and uses a tree. Dictionary is faster but unordered and uses a hash table.

- Use-case for SortedDictionary:

    - Storing and retrieving items where order of keys matters — like leaderboard scores, or alphabetically sorted items.

- What happens if you add the same key twice?

    - Throws ArgumentException.
