# Q5-18: What is the Expression Tree?

- It is a data structure that represents code as a tree of expressions.
- Instead of executing code directly, expression trees represent code as data
- Atree where each node is an expression (like a method call, a variable, a constant, an operator).
- Expression trees let you inspect, modify, or translate code before running it.

- For example, ORMs like Entity Framework use expression trees to translate LINQ queries into SQL.
- This means when you write a query like:
  - dbContext.Users.Where(u => u.Age > 18)
  - the lambda u => u.Age > 18 is turned into an expression tree, which EF parses and converts to SQL.

- Imagine this simple expression: u => u.Age > 18
- The expression tree for it might be:

  - Lambda Expression

    - Parameter: u

    - Body: Binary Expression (>)

      - Left: Member Access (u.Age)
      - Right: Constant (18)

- Expression trees are represented by the types in the namespace System.Linq.Expressions:
- Expression<Func<T, bool>> — represents a lambda expression as a tree.

- Example:

```csharp
Expression<Func<int, bool>> expr = x => x > 10;
var binaryExpr = (BinaryExpression)expr.Body;

Console.WriteLine(binaryExpr.Left);   // x
Console.WriteLine(binaryExpr.Right);  // 10
Console.WriteLine(binaryExpr.NodeType); // GreaterThan
```

- IQueryable uses expression trees to translate LINQ to other languages (like SQL).

    Know the difference between a delegate (code to execute) and an expression tree (data representation of code).

- An expression tree is a representation of code as a tree data structure that allows programs to inspect, modify, or translate code before execution, which is essential for LINQ providers like Entity Framework to translate queries into SQL.”
