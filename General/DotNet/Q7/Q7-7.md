# Q7-7: What is CancellationToken?

- It is used to cancel an asynchronous or long-running operation in a controlled and cooperative way.

- Example

```csharp
public async Task DownloadDataAsync(CancellationToken token)
{
    for (var i = 0; i < 10; i++)
    {
        token.ThrowIfCancellationRequested();

        await Task.Delay(500, token);
        Console.WriteLine($"Downloaded chunk {i}");
    }
}

var cts = new CancellationTokenSource();

var task = DownloadDataAsync(cts.Token);

Task.Delay(2000).ContinueWith(_ => cts.Cancel());

await task;
```

- How It Works:

  - `CancellationTokenSource` = the controller
  - `CancellationToken` = the signal passed to the method
  - `ThrowIfCancellationRequested()` = tells the method to stop

- Where to Use It

| Scenario                  | Why                                               |
| ------------------------- | ------------------------------------------------- |
| API request timeouts      | To abort logic if client disconnects              |
| Background services       | So app shutdown can stop tasks gracefully         |
| Long loops / calculations | So user can cancel operations                     |
| File/database/network I/O | To avoid wasted work when result no longer needed |

- Questions

| Question                                                | Correct Answer                                      |
| ------------------------------------------------------- | --------------------------------------------------- |
| Does `CancellationToken` force stop code?               | No — it's cooperative, code must check it           |
| What happens if you ignore the token?                   | The operation keeps running                         |
| Does `Task.Delay(500, token)` automatically cancel?     | Yes, throws `TaskCanceledException` if cancelled    |
| Should you call `token.ThrowIfCancellationRequested()`? | Yes, if you want to exit early                      |
| Can cancellation tokens be reused?                      | No — each `CancellationTokenSource` is one-time-use |

- Common Pitfalls

| Mistake                                            | Why It’s Bad                                                  |
| -------------------------------------------------- | ------------------------------------------------------------- |
| Not checking `token.IsCancellationRequested`       | Method never stops, even if cancelled                         |
| Creating `new CancellationToken()` manually        | Don’t — always use a source (`new CancellationTokenSource()`) |
