# Q7-9: Explain Multithreading in .NET

- This is essential to prevent race conditions, data corruption, and deadlocks in concurrent code.

- `lock`

  - this keyword ensures that only one thread can access a critical section at a time.

```csharp
private static object _lockObj = new object();

public void Increment()
{
    lock (_lockObj)
    {
        _counter++;
    }
}
```

- Common Mistakes

| Mistake                                     | Why It’s Dangerous                                             |
| ------------------------------------------- | -------------------------------------------------------------- |
| Locking on `this`                           | External code can also lock on it → risk of deadlocks          |
| Locking on a string                         | Strings can be interned — two strings might be the same object |
| Nested locks (A then B, elsewhere B then A) | Classic deadlock scenario                                      |

- `Thread` class

  - Runs a method on a separate OS thread.
  - Lower-level than `Task`/`async`.
  - You manage lifetime, sleep, abort manually.
  - Use only when you need long-lived, manual threading. Otherwise use `Task`, `Parallel`, or async.

```csharp
Thread thread = new Thread(() => DoWork());
thread.Start();
```

- `ThreadPool` and `Task`

  - The `ThreadPool` is a pool of reusable threads for short background work.
  - `Task.Run` uses the ThreadPool.
  - Best for fire-and-forget operations or parallel workloads.

```csharp
Task.Run(() => DoWork());
```

- Race Conditions

  - It happens when two threads access shared data at the same time and the result depends on the order of execution.
  - Two threads modify shared state without sync — unpredictable results.

```csharp
_counter++; // not thread-safe!

//Fixing
lock (_lockObj)
{
    _counter++;
}
```

- `volatile`

  - Use it when one thread writes a variable and others read it without locks.
  - Tells the compiler and CPU not to cache the variable between threads.

```csharp
private volatile bool _cancelled;
```

- `Monitor`, `Mutex`, `Semaphore`, `ReaderWriterLock`

| Primitive          | Use Case                 |
| ------------------ | ------------------------ |
| `lock` (Monitor)   | Simple mutual exclusion  |
| `Mutex`            | Cross-process locking    |
| `Semaphore`        | Allow N threads to enter |
| `ReaderWriterLock` | Many readers, one writer |

- Questions

| Question                                           | Tip Answer                                                                    |
| -------------------------------------------------- | ----------------------------------------------------------------------------- |
| Is `++i` atomic?                                   | No — must use lock or `Interlocked.Increment()`                               |
| What’s the difference between `Task` and `Thread`? | `Task` is higher-level, uses thread pool; `Thread` is lower-level and heavier |
| Can a deadlock happen with `lock`?                 | Yes — if locks are acquired in different orders on different threads          |
