# Q7-8: What happens if we use GetAwaiter, GetResult(), Result, or no await?

- `.Result` and `.Wait()`
  
  - These are synchronous blocking calls.
  - They block the calling thread (especially dangerous on the UI thread or ASP.NET request threads), and can cause deadlocks.

```csharp
var result = myTask.Result;  // blocks until task finishes
myTask.Wait();               // same
```

- Deadlock Example:

  - The async method needs the thread to continue.
  - But `.Result` is blocking it from completing.
  - Mixing `.Result` with async flow blocks the thread that async needs to resume.

```csharp
public IActionResult GetData()
{
    var result = GetDataAsync().Result; // DEADLOCK HERE
    return Ok(result);
}
```

- `.GetAwaiter().GetResult()`

  - This is a lower-level version of `.Result`.
  - It also blocks.
  - Slight difference: It unwraps exceptions. (throws actual cause, not `AggregateException`)
  - Still not recommended — can deadlock just like `.Result`.

```csharp
var result = myTask.GetAwaiter().GetResult();
```

- No await

  - This compiles but doesn’t wait. — can lead to:
    - Lost exceptions
    - Tasks silently failing
    - Hard-to-reproduce bugs

```csharp
public async Task DoSomethingAsync()
{
    SaveToDbAsync(); // ❌ forgot `await` — this runs in background
    await SaveToDbAsync(); // ensures exception is caught and work completes
}
```

- Questions

| Question                                             | Tip Answer                                            |
| ---------------------------------------------------- | ----------------------------------------------------- |
| What's the difference between `.Result` and `await`? | `.Result` blocks the thread; `await` yields it        |
| When can `.Result` cause deadlocks?                  | In synchronization context (UI, ASP.NET)              |
| Is it safe to ignore the returned `Task`?            | No — you can lose exceptions or cause race conditions |

- Best Practices

  - Use `await` always** for async calls.

  - Avoid `.Result`, `.Wait()`, `.GetAwaiter().GetResult()` unless:
    - You're in a console app.
    - You're absolutely sure it can't deadlock.

  - Use `ConfigureAwait(false)` in library code to avoid capturing sync context
