# Q7-11: What are OS-Level Handles?

- OS-level handles (a.k.a. Unmanaged Handles) are low-level identifiers or pointers that the OS uses to keep track of system resources.
- These are outside .NET's memory management, so .NET’s GC doesn't know how to clean them up — that’s why we use `IDisposable`.

- Examples:

| Resource Type    | Description                         | Example Class            |
| ---------------- | ----------------------------------- | ------------------------ |
| File handles     | OS reference to an open file        | `FileStream`             |
| Socket handles   | Reference to a network socket       | `Socket`, `TcpClient`    |
| Database handles | Connection to a database engine     | `SqlConnection`          |
| Thread handles   | Pointer to OS-managed thread        | Low-level threading APIs |

- Explanation

  - When you open a file, the OS returns a handle (like a ticket/ID).
  - That handle points to the open file resource.
  - .NET just wraps that handle in a class (e.g. `FileStream`)
  - When you're done, you must call `Dispose()` to tell the OS to close the handle.
  - Otherwise: the file stays open → memory/file leaks.
  - If a class wraps an OS-level handle, it must implement `IDisposable`.
