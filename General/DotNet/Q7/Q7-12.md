# Q7-12: What is a Memory Leak?

- A memory leak happens when your app keeps using memory it doesn't need anymore, so the garbage collector can't clean it up.
- Over time, memory usage grows unnecessarily and can slow down or crash your app.

- It happens when:

| Scenario                                         | Why it leaks                                        |
| ------------------------------------------------ | --------------------------------------------------- |
| You forget to `Dispose()` unmanaged resources    | OS memory (file handles, DB connections) stays open |
| You keep long-lived references to unused objects | GC thinks you're still using them                   |
| Static fields hold onto large objects            | GC won’t collect them until app ends                |
| Event handlers aren't unsubscribed               | Publishers keep objects alive                       |

- Example

  - The `Subscriber` is subscribed to the publisher's event.
  - Even if `Subscriber` is no longer needed, GC won't collect it because `Publisher` holds a reference to it via the event.
  - You must manually unsubscribe or use `WeakEvent` patterns.

```csharp
public class Publisher
{
    public event EventHandler SomethingHappened;
}

public class Subscriber
{
    public Subscriber(Publisher p)
    {
        p.SomethingHappened += (s, e) => Console.WriteLine("Event!");
    }
}
```

- Questions

| Question                      | Correct Answer                                                   |
| ----------------------------- | ---------------------------------------------------------------- |
| Can managed code leak memory? | Yes — if objects are still referenced or events not unsubscribed |
| What’s the impact of a leak?  | Increased memory use → slow app → crash (OutOfMemory)            |
