# Q7-4: What is the difference between Collect, Dispose, Finalize, and Destructor?

- `Dispose()`

  - Manual Cleanup
  - Releases unmanaged resources
  - Called explicitly by code (or via `using` block)
  - Part of the `IDisposable` pattern

```csharp
using (var file = new FileStream("file.txt", FileMode.Open))
{
} // Dispose() is called here
```

- `Finalize()`

  - Called by the GC if `Dispose()` wasn’t called
  - Allows last chance to release unmanaged resources
  - Very slow & unpredictable → avoid when possible
  - You never call it directly.

- Destructor

  - Finalize Shortcut
  - Syntactic sugar for writing a `Finalize()` method
  - Not recommended for most modern code
  - Only use if managing unmanaged memory directly

```csharp
~MyClass()
{
    // logic here is called in Finalize()
}
```

- Compiler turns this into a `Finalize()` method:

```csharp
protected override void Finalize() { ... }
```

- `GC.Collect()`

  - Forces .NET to run GC immediately
  - Expensive — freezes the app temporarily
  - Should almost never be used in real-world code

- The Full Lifecycle

  1. You create an object.
  2. You use it in code.
  3. You either:
     - Call `Dispose()` manually
     - Or let the GC clean it up (maybe calls `Finalize()`)
  4. Object memory is eventually released by GC.

- Questions:

| Question                                                    | Tip Answer                                      |
| ----------------------------------------------------------- | ----------------------------------------------- |
| Does `Dispose()` call `GC.Collect()`?                       | No — Dispose just releases unmanaged resources  |
| What’s the difference between `Dispose()` and `Finalize()`? | Dispose is manual, Finalize is automatic backup |
| Can I override `Finalize()`?                                | Yes, but normally use a destructor              |
| Is Finalize deterministic?                                  | No — you don’t know when it will run            |

- Best Practice

  - Use the full Dispose pattern with Finalizer backup only when needed:

```csharp
public class MyResource : IDisposable
{
    private IntPtr unmanagedPtr;
    private bool disposed;

    ~MyResource() // Finalizer
    {
        Dispose(false);
    }

    public void Dispose()
    {
        Dispose(true);
        GC.SuppressFinalize(this); // Prevent finalizer
    }

    protected virtual void Dispose(bool disposing)
    {
        if (disposed) return;

        if (disposing)
        {
            // Free managed resources
        }

        // Free unmanaged resources
        Marshal.FreeHGlobal(unmanagedPtr);
        disposed = true;
    }
}
```

- Summary:

| Method/Term          | Who Calls It                        | Purpose                                     | Used For               |
| -------------------- | ----------------------------------- | ------------------------------------------- | ---------------------- |
| `Dispose()`          | Developer / `using`                 | Immediate cleanup of unmanaged resources    | Unmanaged resources    |
| `Finalize()`         | GC (internally)                     | Backup cleanup if `Dispose()` wasn’t called | Unmanaged resources    |
| Destructor (\~Class) | Compiler-generated for `Finalize()` | Defines what to run in `Finalize()`         | Unmanaged resources    |
| `GC.Collect()`       | Developer (not recommended)         | Forces garbage collection                   | Special/debug use only |
