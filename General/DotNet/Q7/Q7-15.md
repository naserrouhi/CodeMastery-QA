# Q7-15: What is the Async State Machine?

- When you mark a method as `async`, the compiler transforms your method into a state machine class behind the scenes.
- Without the state machine, the method couldn’t pause and resume without blocking a thread.

- This class:

  - Tracks where the method left off when it hits `await`.
  - Can pause and later resume.
  - Manages things like `await`, exceptions, and return values

- Think of it like:

  - Imagine you’re reading a book, and someone says: “Pause at page 5 and come back later.”

  - You:
    - Put a bookmark. (state)
    - Do something else. (return control)
    - Come back later and resume from that page.

- Example

```csharp
public async Task<int> AddAsync()
{
    var a = 1;
    var b = await GetBAsync(); 
    return a + b;
}

// The compiler generates this:

```csharp
private sealed class AddAsyncStateMachine : IAsyncStateMachine
{
    public int state; // like page number
    public AsyncTaskMethodBuilder<int> builder;
    private int a;
    private Task<int> bTask;
    private int b;

    public void MoveNext()
    {
        try
        {
            if (state == 0)
            {
                a = 1;
                bTask = GetBAsync();
                state = 1;
                var awaiter = bTask.GetAwaiter();

                if (!awaiter.IsCompleted)
                {
                    builder.AwaitOnCompleted(ref awaiter, ref this); 
                    return;
                }

                b = awaiter.GetResult();
            }
            else if (state == 1)
                b = bTask.Result;

            builder.SetResult(a + b);
        }
        catch (Exception ex)
        {
            builder.SetException(ex);
        }
    }

    public void SetStateMachine(IAsyncStateMachine stateMachine) { }
}
```

- Explanation:

| Part               | What It Does                                              |
| ------------------ | --------------------------------------------------------- |
| `state`            | Keeps track of where the method paused. (like a bookmark) |
| `MoveNext()`       | Runs the next step in the async method.                   |
| `builder`          | Helps construct the `Task` returned to the caller.        |
| `AwaitOnCompleted` | Registers continuation to resume later.                   |
| `GetResult()`      | Resumes the method after the awaited task is done.        |

- How does the async state machine prevent thread blocking?

1. Instead of waiting on the result synchronously (which would block the thread), the method:

   - Exits immediately.
   - Returns a `Task` to the caller.
   - Schedules a continuation to resume later.
   - So, the thread is freed up and can do other work.

2. The `MoveNext()` method is only called when needed — not looping.

   - The state machine is not a background loop — it moves only one step at a time.
   - When an awaited task completes, it calls `MoveNext()` once to resume the method.
   - That’s how we get non-blocking pause & resume — no thread is stuck waiting.

| Step | What Happens                                                                 |
| ---- | ---------------------------------------------------------------------------  |
|  1   | Your `async` method starts and runs until the first `await`.                 |
|  2   | At `await`, it checks if the `Task` is done:                                 |
|      | → If not done, it registers a continuation. (using `AwaitUnsafeOnCompleted`) |
|      | → This continuation will call `MoveNext()` again when the task is complete.  |
|  3   | Once the awaited `Task` finishes, the runtime calls `MoveNext()` again.      |
|  4   | The method resumes where it left off.                                        |

- This continues until the method finishes or throws.

- Visual Flow:

async method called
   ↓
runs until `await`
   ↓
pauses (returns Task) → thread is free
   ↓
awaited Task completes
   ↓
runtime calls stateMachine.MoveNext()
   ↓
resumes from await → next await or return

- Code Flow:

```csharp
var awaiter = task.GetAwaiter();
if (!awaiter.IsCompleted)
{
    state = 1;
    builder.AwaitOnCompleted(ref awaiter, ref this); // registers MoveNext as continuation
    return;
}

// Then, when `task` completes:

MoveNext(); // called automatically by runtime
```

- So What Makes It Non-Blocking?

  - You don’t use `task.Wait()` or `.Result`.
  - The method yields control to the caller immediately.
  - The CPU and thread are free during I/O wait.
  - Execution resumes later, without needing to block anything

- Questions

| Question                            | Best Answer                                                 |
| ----------------------------------- | ----------------------------------------------------------- |
| Does `await` block a thread?        | No — it pauses the method, not the thread.                  |
| What is `MoveNext()`?               | It’s the method the state machine uses to resume execution. |
| Who calls `MoveNext()`?             | The runtime calls it when an awaited task finishes.         |
| Is `MoveNext()` looping constantly? | No — it runs once per continuation step.                    |
| Why is async code scalable?         | It frees up threads by not blocking them on I/O.            |
